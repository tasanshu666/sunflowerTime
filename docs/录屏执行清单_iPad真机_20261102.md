## 1.5 🔴 「先跑一遍验证」与「录到首启同意页」怎么两全

**矛盾**：苹果要求录屏 `from launching the app`，且回复文稿承诺了 `first-run consent`；但先跑一遍验证不崩，同意标记就写进本地了，第二次启动直接进主页 —— 少了这一段。

**解法：不用卸载重装，App 自带「删除数据」。**

代码事实（2026-11-02 核实）：
- 同意标记存 SharedPreferences（`consent_policy_version` / `first_launch_consented` / `consent_accepted_at_ms`）
- 家长端「设置 → 删除数据」走 `DataManagementService.clearAll()`，内部依次清 **Drift 全表 + 安全区 PIN + `SharedPreferences.clear()`**
- 清完 `context.go('/')`，路由守卫检测到「未同意」会**立即重定向回 `/consent`**

所以「跑一遍 → 删数据 → 录屏」可以同时拿到真机 QA 结论和干净的首启画面。

### 操作顺序（严格照做）

| 步 | 动作 | 说明 |
|---|---|---|
| 1 | **完整跑一遍 2105** | 同意页 → 建/选任务 → 专注 → 结算 → 花园 → 家长区设 PIN → 审批 → 报告 → 会员页。**崩了/白屏/冒中文就停下报我** |
| 2 | 家长端 → **设置** tab → 拉到最底 → **删除数据** | 入口在 `parent_settings_page.dart:487` → `/parent/delete` |
| 3 | 弹窗点确认 | 会提示「先导后清」（导出功能留 V2，此处只是提示，不影响） |
| 4 | App 自动跳回**同意页** | 说明标记已清干净 |
| 5 | 🔴 **把 App 从后台彻底划掉**（上滑手势） | 录屏要的是**冷启动**，不能是热恢复 |
| 6 | 开始录屏 → 回桌面 → 点图标 | 这样第一帧就是真正的启动 → 首启同意页 |

### 删除会清掉什么（都要重新来一遍，这是预期的）

| 项 | 结果 | 对录屏的影响 |
|---|---|---|
| 同意标记 | 清空 → 回到同意页 | ✅ 正是想要的效果 |
| 家长 PIN | 清空 → 可重新「首次设定」 | ✅ 分镜 57–72s 要的就是首次设定 PIN |
| 成长任务 | 清空，但**首次建库会播种 5 条模板任务**（作业/口算等） | ✅ 孩子端首屏就有任务可点，分镜不用改 |
| 花园 | 清空 | ✅ **向日葵是免费初始物种**（阳光价/碎片价均为 0），可现场种一株 |
| 阳光余额 | 归零 | ✅ 跑一次专注约得 12☀，浇水 5☀、施肥 10☀ —— 闭环成立 |
| 报告/记录 | 归零 | ⚠️ 所以录屏必须**先跑专注再进报告页**（分镜 12–27s 在前，72–95s 在后，顺序天然正确） |

> 🔴 第 1 步跑完记得把当时设的 PIN 记下来（进家长区做第 2 步要用）；删完就作废。

## 1.6 🔴 内购段怎么录（沙盒账号，真机正确登录姿势）

### ✅ 最终决定（2026-11-02 玄参拍板）：放弃沙盒，走「只展示」版

沙盒账号在 iOS 26.7.2 上连续三种报错（密码不正确 → 不允许创建 iTunes 账户 → 无法用于 iTunes Store），判定为账号状态问题、时间成本不划算。**改用真实 Apple ID + 只展示会员页。**

**依据**：`docs/审核回复_2.1_InformationNeeded_20261030.md` §3 第 7 条原文写的是
> Navigation to the purchase flow: ... → the premium page → "Unlock now" (price is loaded from the App Store) or "Restore purchases".

即苹果要的是「**到达购买页的路径 + 价格由 App Store 加载 + 恢复购买入口**」，**没有要求录到购买确认框**。所以：

| 动作 | 做不做 | 原因 |
|---|---|---|
| 停在会员页 5 秒 | ✅ **必须** | 价格 `US$14.99`（由 StoreKit 加载）+ 6 项权益对比表 + `Restore purchases` 全在这一屏 |
| 点 `Restore purchases` | ✅ 推荐 | 零风险、不需密码、证明 StoreKit 事务通道可用；弹「无购买可恢复」点 OK 即可，属正常结果 |
| 点 `Unlock now` | 🔴 **禁止** | 真实账号会弹「验证 1007681634@qq.com」密码框 → 暴露个人邮箱，且卡 `Purchasing...` |

下面沙盒相关步骤保留备查，**本批不执行**。

**首次录屏踩到的坑（2026-11-02 实例）**：点 `Unlock All` 后弹出的是

> Apple Account Verification — Enter the password for "1007681634@qq.com" in Settings.

底部一直 `Purchasing...` 卡住。两个问题：① 屏幕暴露真实 Apple ID；② 这不是购买确认框，流程没走完也没干净取消。

**根因**：设备上登录的是真实 Apple ID，App Store 不走沙盒环境。

### 沙盒账号为什么在「设置」里找不到

真机的「设置 → App Store → **沙盒账户**」**只在登录过之后才出现**，它是「查看/退出已登录沙盒账号」的入口，**不是首次登录入口**。首次登录必须由购买流程触发。

### ⛔ 报错「不允许在 iTunes 中登录 / 不允许在此 Apple 账户下登录」

**这不是账号建错了，是位置错了 —— 沙盒账号天生不能在「商店层」登录。**

沙盒测试员是 App Store Connect 里造的**假账号**，不是真 Apple 账户，iOS 的「设置 → App Store / 媒体与购买项目」只接受真 Apple 账户，所以一律拒绝。它唯一被接受的地方是**购买时弹出的那个登录框**。

同理，如果弹的是这句话：

> Apple Account Verification — Enter the password for **"1007681634@qq.com"** in Settings.

说明这个框的 Apple 账户**已经被写死成真实账号了**，你在里面输沙盒密码当然失败。要先「退掉真实商店账号」，让系统弹出一个**可填新账号**的框。

**判定标准**（三条全中才算成功）：
1. 对话框里有**可编辑的 Apple 账户邮箱**输入位（不是只有密码）
2. 登录后确认框一角出现 **`[Environment: Sandbox]`**
3. 商品价格仍是 `US$14.99`（不是空白 / 不是 `Unavailable`）

### ⛔ 报错「验证失败 · 你的 Apple 账户或密码不正确」（2026-11-02 实况）

**先恭喜一句：弹出这个框说明位置已经对了。** 框里能填邮箱、能填密码，就是正确的沙盒登录入口。设备**不需要事先"知道"沙盒账号** —— 它是在你按下「好」的那一刻，把这对凭证送去 App Store 服务器校验。报"密码不正确"＝服务器拒绝了这对凭证，**不是位置问题**。

**按下面顺序排（命中率从高到低）：**

**① 取消勾选「中断此测试员的购买流程」** 🔴 截图里这项是**勾着的**
> 它的作用：该测试员每次购买时，苹果会**故意用更新的条款与条件打断购买流程**，好让你测试 App 对中断的响应。
> 后果：就算密码对了，录制时也弹不出干净的购买确认框，会变成 T&C 弹窗。**必须取消勾选再存储。**

**② 在 ASC 重置沙盒密码（最可能的元凶）**
沙盒 → 测试员 → 点 `sandbox@sunflowertime.app` → **编辑** → 重设密码 → 存储 → **等 5 分钟**再试。

| 密码要求 | 说明 |
|---|---|
| ≥8 位 | 少一位 ASC 直接不收 |
| 含**大写 + 小写 + 数字** | 缺一样不行 |
| 只用 ASCII | 别带空格、中文、特殊符号 |

建议直接设 `Test1234`（录屏时手输不易错）。**重置还有副作用好处：连续失败多次后沙盒测试员会被锁，重置密码同时解锁。**

**③ 输入细节（三个隐形杀手）**
- **首字母被自动大写**：iOS 键盘默认句首大写，密码首字母若是小写就废了 → 逐字看一遍
- **自动填充塞了真实 Apple ID 密码**：长按密码框 → 全选 → 删干净 → 手动逐字输
- **尾随空格**：从备忘录或密码管理器粘贴时常带一个空格
- **VPN / 代理**：有的话先关掉，StoreKit 请求走代理可能直接被拒

**④ 还不行 → 换一个新测试员**
用另一个全新邮箱（如 `sandbox2@sunflowertime.app`）再建一个，密码同上。比在原账号上反复试快得多。

**🔴 止损线**：第 ① ~ ④ 加起来超过 **15 分钟**仍不通 → 立刻转 🅱 保底方案。苹果审核内购自己会用沙盒跑，不靠你的录屏。

### ⛔ 报错「不允许创建 iTunes 账户 · 此 Apple 账户目前无法用于 iTunes Store，请稍后再试」

**这是进展，不是倒退。** 说明密码已经被接受，卡点换成了「账号状态」。

**为什么会出现这句**：iOS 走进的是**新建商店账户**的判定分支 —— 它没把这个沙盒账号认成"已存在的商店账户"，于是尝试走创建流程，而创建被苹果封了，就报这句。叠加"请稍后再试"，通常意味着**连续失败后账号被临时锁 + 缓存了坏状态**。

**处置顺序（总预算 15 分钟，超时转 🅱 保底）：**

| 步 | 动作 | 耗时 |
|---|---|---|
| 1 | **立刻停手**，别再连点重试（越试锁越久） | — |
| 2 | iPad **关机重启**（清掉 StoreKit 卡死的认证状态） | 2 min |
| 3 | 重启后「设置 → 顶部名字 → 媒体与购买项目」确认**仍是退出状态**；不是就再退一次 | 1 min |
| 4 | ASC 里**再重置一次**沙盒密码，**等 15 分钟** | 15 min |
| 5 | 只试**一次**：App → `Unlock All` → 填邮箱密码 | 1 min |

**若第 5 步仍是这句 → 换第二入口（推荐，绕开商店账户路径）**

设置 → 隐私与安全性 → **开发者模式** → 打开 → 重启 iPad → 设置里出现 **开发者** 菜单 → **沙盒账户 / Sandbox Apple Account** → 在这里直接登录沙盒账号

> 这条路不经过「商店账户创建」判定，正是苹果给开发者准备的沙盒专用入口。代价是要开开发者模式并重启一次（2 分钟）。
> 登录成功后再回 App 点 `Unlock All`，应直接出 `[Environment: Sandbox]` 确认框。

## 2.5 🔴 专注时长铁律：不满 5 分钟 = 阳光 +0

**首次录屏踩到的坑**：选了 1 分钟任务、跑 24 秒，结算页显示

```
This Session      24 s
Sunlight Earned   +0
Too short — the sunflower collected nothing (output starts at 5 min)
```

这直接把 App 的核心价值（专注 → 换阳光 → 养花）演成了「零收益」，而且那句话读起来像 App 在拒绝奖励用户。**剪不掉，只能重录。**

### 规则与对策

| 项 | 值 |
|---|---|
| 阳光产出起点 | 专注 **≥ 5 分钟** |
| 产出速率 | 1 分钟 = 1☀ |
| 浇水成本 | 5☀ / 施肥 10☀ |
| **重录建议** | 选 **10 分钟任务**，**跑满 6 分钟**（→ 6☀，够浇一次水） |

### 怎么在 120 秒里装下 6 分钟专注

**后期剪掉等待段**，苹果接受剪辑（看的是流程连贯，不是实时性）：

- 专注计时页保留**开始 3 秒**（让计时器跑起来）
- 中间 5 分多钟整段剪掉
- 保留**结束前 3 秒** → 接结算页

所以录制时**一次连续录完整流程**（总长约 8–10 分钟），后期再剪成 110 秒左右。不要分段录再拼，那样容易跳帧不连贯。

## 2. 录屏前 10 分钟准备（iPad 设置）

| # | 设置项 | 操作 | 原因 |

| 1 | **语言** | 设置 → 通用 → 语言与地区 → iPad 语言 → **English** → 继续 → 设备会重启一次 | 苹果是英文审核，中英混杂会被追问「这个中文是什么」 |

| 4 | 自动锁定 | 设置 → 显示与亮度 → 自动锁定 → **永不** | 中途锁屏录屏会断 |
| 5 | 亮度 | 手动拉到 **80% 以上**，关自动亮度 | 录出来太暗审核员看不清 |
| 6 | 屏幕录制加到控制中心 | 设置 → 控制中心 → 把「**屏幕录制**」加进「包含的控制」 | 不然录不了 |

## 3. 分镜脚本（iPad 版 · 成片目标 110–120 秒）

> **竖屏录**（你首版就是 1640×2360 竖屏，保持即可，与 iPhone 截图观感一致，审核员对照更顺）。**全程不要转屏**。
>
> 关键：**一次连续录制完整流程（约 8–10 分钟）**，后期把专注等待段剪掉，成片压到 120 秒内。不要分段录再拼。

| 成片时间 | 录制时怎么操作 | 剪辑处理 |
|---|---|---|
| **0–3s** | 开始录屏 → 回桌面 → **点 App 图标** | 直出。苹果原文 `from launching the app`，这一帧不能省 |
| **3–12s** | 首启同意页 → 直接点 **`Let's Start`** | 直出。🔴 **不要点 `View full privacy policy`**（首版在这白耗 12 秒） |

| **22–28s** | 专注计时页跑起来 | 保留**开始 3 秒** + **结束前 3 秒**，中间剪掉 |
| ⏳ 录制中 | 🔴 **真实跑满 6 分钟**（10 分钟任务不必跑完，满 5 分钟就有阳光） | **整段等待剪掉** |
| **28–38s** | 结束专注 → `Focus Finished` 结算页 | 直出，**让 +N☀ 动画播完**。🔴 这里必须是正数，出现 `+0` 就作废重录 |
| **38–52s** | 花园 → 点空盆 → 种 **Sunflower（免费）** → 点 **`Water −5☀`**，看到进度条动 | 直出。🔴 必须真的扣阳光、进度条真的走。不要点 `Fertilize`（10☀ 不够） |
| **52–68s** | 点右上角 Parent Hub → **`First time here — set a parent PIN`** → 输入 `1234` → `Set PIN & enter` | 直出。🔴 苹果最爱追问的点，PIN 键盘要清晰 |
| **68–88s** | 家长端：任务列表（5 条模板任务）→ 切到报告/记录页（此时已有 1 条专注数据） | 直出。**不要点 `Edit child`、模板、设置页**（首版在这逛了 90 秒） |
| **88–112s** | **Mine** → 金色卡 → 会员页 → 点 `Unlock All` → **沙盒确认框出现** → 点 **`Cancel`** | 直出。确认框要完整出现（见 §1.6；走不通就用保底方案点 `Not Now`） |

## 5. 传到 Mac 并压缩

**传输**：iPad 照片 App → 选中视频 → 分享 → **AirDrop** → 选你的 Mac mini。

**压缩**（Resolution Center 附件有大小限制，压到 **≤50MB**）：

```bash
# 竖屏用这条（高度限 1080）
ffmpeg -i 录屏.mov -c:v libx264 -preset slow -crf 26 -vf "scale=-2:1080" -c:a aac -b:a 96k -movflags +faststart 录屏_1080p.mp4

# 横屏用这条（宽度限 1920）
ffmpeg -i 录屏.mov -c:v libx264 -preset slow -crf 26 -vf "scale=1920:-2" -c:a aac -b:a 96k -movflags +faststart 录屏_1080p.mp4
```

压完检查：

```bash
ls -lh 录屏_1080p.mp4        # 体积 ≤ 50MB
ffprobe -v error -show_entries format=duration -of csv=p=0 录屏_1080p.mp4   # 时长 60~120 秒
```

> 若压完仍 >50MB：把 `-crf` 从 26 调到 30，或把时长剪到 90 秒内。

## 8. 最容易踩的六个坑

1. **从 App 内部开始录** → 苹果原文要 `from launching the app`，必须从桌面图标开始
2. **没录到 PIN 键盘** → 家长区门禁是 2.1 里最常被追问的点，PIN 确认页必须清楚
3. **没录内购确认框 / 真买了** → 要「弹出来再取消」，不要真付，也别跳过
4. **录屏里有中文** → 说明 i18n 有漏点，先停下报我，别硬录
5. 🔴 **专注不到 5 分钟** → 阳光 +0，价值闭环断裂，且结算页会明写「collects nothing」，剪不掉只能重录（详见 §2.5）
6. 🔴 **点进隐私政策全文 / 在家长端闲逛** → 前者白耗 12 秒，后者让审核员看到 `Edit child`、模板、设置等与审核无关的页，压缩到 25 秒内
