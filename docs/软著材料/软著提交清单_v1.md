## 2. 🔴 提交前必须处理的 4 件事

### 2.1 官方申请表必须线上生成，本 docx 只是草稿
中国版权保护中心的申请表**只能在线填报后自动生成 PDF**，不能自制。
- 本地这份 `软著申请表_向日葵专注.docx` 用途 = **把里面的字段抄到官网上**（相当于填报草稿）
- 官网：`register.ccopyright.com.cn` → 注册 → 机构用户实名 → 计算机软件著作权登记

### 2.2 「软件主要功能」字数：新版要求 500–1300 字
- 2026-03-15 起启用**新版申请表**，该栏从「200字以内」改为 **500–1300 字**，且须覆盖：研发背景 / 核心架构 / 功能模块 / 技术实现 / 应用场景
- **本项目当前正文 727 字** ✅ 落在区间内，但需确认新系统填报时是否需补齐 5 个维度
- 另：官网系统会自动生成**签章页**，其中「经办人」需**本人手写签名 + 填身份证号**，并**手抄**承诺文字（含「未使用 AI 开发编写代码、撰写文档或生成登记申请材料」）

> ⚠️ **这条承诺必须如实评估后再签。** 代码与文档是 AI 辅助产出的，签字即承担个人责任（含列入失信名单 + 个人征信）。请自行判断并与代理沟通，不要照抄他人版本。

### 2.3 代码行数与开发完成日期要跟当前仓库对齐
| 项 | 表里写的 | 仓库实际（2026-11-10 实测） |

| 开发完成日期 | `2026-10-10` | `lib/ 最后提交 2026-11-10` |

**规则**：开发完成日期必须 **≥ 源码最后修改日**，且 ≤ 申请日。
→ 二选一：
- **A（快）**：沿用现有 40653 行 / 2026-10-10，**不重新生成源码材料**。但仓库代码已远超当日，源码材料只反映 10 月初状态 → 审查时「材料与代码脱节」有风险
- **B（稳）**：改 `generate_ruanzhu.py` 的 `C["dev_complete"]` 与 `C["code_lines"]`，**重跑脚本重新生成全套**（需 `pip install python-docx`），开发完成日期填 `2026-11-10`
