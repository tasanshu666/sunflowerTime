### 4.1 常量

| 常量 | 值 | 说明 |
|---|---|---|
| `kGardenWeatherBadgeShelterSize` | **72** | **预留盒**，不是「画出来的盾牌有多大」 |

| `kGardenWeatherBadgeShelterGap` | **7** | 盒间距；因内容右缘贴盒右缘，它同时是**视觉**间距 |
| `kGardenWeatherBadgeShelterKey` | `'garden_weather_badge_shelter'` | widget 测试定位 |

### 4.2 为什么要按 bbox 裁（四件视觉差 1.7 倍）

`shelter_*.webp` 是 288² 画布 + 大量透明边距，`BoxFit.contain` 直接缩会把留白一起缩进去：

| refType | 内容 bbox（288 画布） | 实际尺寸 | 占画布 |
|---|---|---|---|
| `shelter_shade` 遮阳棚 | (45,38)-(254,249) | 209×211 | 72.6% × 73.3% |
| `shelter_rain` 遮雨棚 | (77,45)-(219,243) | 142×198 | **49.3%** × 68.8%（最瘦） |
| `shelter_warm` 保温棚 | (30,57)-(259,226) | 229×169 | 79.5% × 58.7% |
| `shelter_wind` 挡风板 | (22,87)-(268,210) | 246×123 | 85.4% × **42.7%**（最扁） |

测量方式：alpha > 8 取 bbox，除以 288。**表在 `kGardenWeatherBadgeShelterArtContentBBox`**（归一化 `Rect`）。

算法（等比、不拉伸）：

```
c        = artMaxSide / max(bbox.w, bbox.h)   // 整张画布要画多大
contentW = bbox.w * c ;  contentH = bbox.h * c
left     = boxSize - contentW - bbox.left * c // 内容贴盒右缘
top      = (boxSize - contentH) / 2 - bbox.top * c
```

- 缺表（未知 refType）⇒ 按「整画布」兜底（等价旧 contain，绝不抛异常）；`shelterArtPathOf` 返回 null ⇒ 回退 Material 盾牌图标（`errorBuilder` 同样兜住解码失败）。

### 4.3 🔴 盒 72 不参与行高

```
Row(min, center)
  ├─ SizedBox(width: 72×s, height: 56×s)      ← 高只有 56
  │    └─ OverflowBox(min/max = 72×s)          ← 上下各溢 8pt（透明的留白）
  │         └─ SizedBox(72×s) → _ShelterArtFilled
  ├─ SizedBox(width: 7×s)
  └─ SizedBox(56×s) → 状态灯
```

**为什么不让行高变 72**：宿主 `Positioned(right:12, top:12)` 锚顶。行高一旦变 72，状态灯会被挤到 `top:20` ⇒ **买棚那一刻天气框往下跳 8pt**（新缺陷）。行高钉 56 ⇒ 状态灯 `top` 恒 12（与 A2/A3 全部基线一致），盾牌向上溢出的部分落在 chips 行右侧的空白处。

### 4.4 显示条件（与 done 解耦）

```dart
showShelter = shelterBought && banner.shelterRefType != null
```

- `shelterRefType != null` ⇒ 当日**确有推荐棚**（极端日）。温和日即便 `shelterBought` 为真也不显示（那天没有「该搭的棚」）。
- **与 done 解耦**：盾牌只表达「棚已买」；对勾表达「今日已完成」。当前判据下两者同真，但**语义不同源**，不要合并条件（将来若 done 判据再变，盾牌不受影响）。

### 8.5 🔴 时间接缝纪律（根因 A：本批最贵的一条）

**现象**：云影 / 叶片 / 雪花「走到右边突然回到左边」，每一类都在**同一个位置**跳。

**旧实现**：`cycle = frac(phase + progress × speed)`，`speed` 是「每 12s 走几圈」的**小数**。controller 由 1 归 0 的那一帧，相位从 `frac(phase + speed)` 直接跳回 `frac(phase)` ⇒ 瞬移 `frac(speed) × 行程`。

**实测每缝跳变量**（390×844，相邻两帧）：

| 元素 | 接缝位移 | 正常一帧 |
|---|---|---|
| 云影（多云/阴） | 36.0 / 17.0 pt | 0.05~0.6 pt |
| 叶片 | 283.7 pt | 同上 |
| 风线 | 371.0 pt | 同上 |
| 小雨 | 534.3 pt | 同上 |
| 暴雨 | 593.9 pt | 同上 |
| 雪花 | 487.3 pt | 同上 |
| 热浪 | 747.9 pt | 同上 |
| 光斑（orb） | 16.10 pt（上限 1.04 pt） | 同上 |

⇒ 跳变是正常速度的**数十~上千倍**，且与「横飘 / 下落」无关 —— 是**周期接缝处的相位断裂**。

**修法**：

1. 主循环拉长到 `kGardenWeatherFxLoopPeriod = 12 分钟`（= `kGardenWeatherFxPeriod` 12s × `kGardenWeatherFxLoopFactor` 60）。`kGardenWeatherFxPeriod` 只是 `speed` 字段的**参考周期**，不是 controller 周期。
2. 每颗粒子 `cycles = max(1, round(speed × 60))` —— **整数**。于是 `cycle(1) = frac(phase + cycles) = frac(phase) = cycle(0)`，**逐位闭合**。
3. 速度观感几乎不变（圈数取整偏差 ≤ 半圈 / 12 分钟）。

🔴 **后人必守**：新增任何循环元素，`cycles` 必须是整数（生成侧已统一 `round`），且**不许**为了「快一点」把 controller 周期改短 —— 周期一短，取整误差就会变成可见的速度差。

附：光斑走的是**正弦闭路**（`sin/cos(cycle·2π)`，起止同位），本身没有回绕点；它的 16.10pt 是「相位断裂把闭路切成两段」的下游表现，修法同样是整数圈数。

### 8.6 🔴 可见区与余量纪律（根因 B / C）

**根因 B：动效层 rect 只有屏高的 64%**

挂载点当年写 `height: gardenPotAreaBottom(size)`（背景菜地上沿）。实测 `getRect(kGardenWeatherFxKey)` vs `Scaffold` body：

| 视口 | 动效层高 | 屏高 | 差 | 占比 |
|---|---|---|---|---|
| 390×844 | 542.4 | 844 | 301.6 | **35.7%** |
| 360×780 | 500.9 | 780 | 278.9 | 35.8% |
| 430×932 | 598.7 | 932 | 333.3 | 35.8% |
| 768×1024 | 749.0 | 1024 | 275.0 | 26.9% |

⇒ 层底以上的雪花 / 雨丝被 `clipRect` 硬切：「飘着飘着突然没了」（再叠根因 A 就是「跳一下」）。

**修法**：层高覆盖**整屏**（`height: size.height`），纵向行程以**可见区 rect** 为基准（可参数化，默认 = 层 rect）；雨滴「落地」仍钉在**背景菜地上沿**（页面传 `groundY`）—— 水花不该被推到屏幕最底（那里会被底栏挡掉）。

**根因 C：模糊光晕没算进余量**

云影 `MaskFilter.blur(sigma = 10)`，可见光晕 ≈ 3σ = **30pt**，而余量只有 `kGardenWeatherFxWrapMargin = 12` ⇒ 几何上「整颗已出屏」时光晕还挂在屏内。**修法**：云影行程两端各再加 `cloudHalo = 3σ`（**等效余量 12 → 42**）。

**横飘元素活动带仍只占上方 66%**：这是刻意的（云 / 叶 / 风线只掠过植物区，满屏横飞会很吵）；只有**纵向**（雨 / 雪 / 暖尘 / 热浪）放满整屏。

### 8.7 进出场 α 斜坡（兜底）

- 每类元素按「包围盒到可见区边缘的距离」算 α：进入侧 **8% 视野宽/高** 从 0 → 1，离开侧 1 → 0；斜坡长度至少半个元素尺寸（大云影按「已露出比例」淡入）。
- **斜坡只作用在该元素的运动轴上**（横飘只看 x，下落 / 上浮只看 y）。否则贴着屏幕左边的雪花会被误判成「正在入场」而整体偏暗。
- `opacity == 0` ⇒ 这一帧不画（`isVisible` 为假），探针也不追究位移 —— 这就是「回绕必须发生在看不见的时候」的**统一口径**。

### 8.8 探针验收（不许靠肉眼）

| ⑬ 相位闭合 | `cycleOf(p,1) ≈ cycleOf(p,0)`（1e-12）+ 两侧坐标逐位相同（1e-9） |
| ⑭ 玄参点名采样 | 云 / 叶 / 雪在 0.98 / 0.995 / 0.9999 / 0 / 0.0001 / 0.005 的坐标打表；过缝那一对必须只剩「1/10000 圈」的正常位移（唯一例外：跨越自身回绕点且两端都不可见） |
| ⑮ 周期与圈数 | `loop == period × factor`；每颗 `cycles` 为正整数且来自 `speed` |
| ⑯ 雪花纵向 | 不再是「层底裁切」，而是整屏 + 底部余量 |
| ⑰ 兼容性 | 把可见区参数化成「比层更矮的花园带」也不会露出回绕点 |

🔴 **验收方法论（本批最贵的教训）**：探针**必须先在旧实现上红**才算有效。
证据：旧实现下 orb 接缝 16.10pt vs 上限 1.04pt（16 倍），云 / 叶 / 雪 / 雨 / 热浪全部超限 —— 这叫「有鉴别力」。只跑新实现、看到全绿就收工，等于什么都没验（第一次修「跳变」时正是这么误判成「回绕点位置问题」，没修时间接缝，于是**复发了一次**）。

### 8.9 性能口径

- 单帧 draw 对象 ≤ **220**（暴雨 ≈ 170 最重）；全是线段 / 圆 / 一条渐变矩形。
- **不每帧 new 渐变**：光斑径向渐变按「半径桶 + α 桶」缓存；热浪描边按「线长 / α / 线宽」缓存；光束 / 雨雾 / 暗角按画布尺寸缓存；`Paint` / `Path` / `MaskFilter` 全部复用（稳态零 Paint 分配）。
- `GardenWeatherFxSample` 是每帧每颗可见粒子一个小的不可变记录（center + bounds + opacity），量级与旧实现每帧现算的 `Rect`/`Offset` 相同；换来的是**绘制坐标与探针坐标同源**。
- 本层**零文字**（不做每帧文字布局）。

### 8.10 挂载位置与层级

```
garden_page 根 Stack
  ① background（BoxFit.cover）
  ② GardenWeatherFx（Positioned(left:0,right:0,top:0,height:size.height)）← 整屏
  ③ content（植物网格 / 卡片）
  ④ 木牌热区（Positioned.fromRect）
  ⑤ chips 行 / 天气状态灯（right:12, top:12）
  ⑥ 一键 FAB（right:12, bottom:12）
```

- 动效在**背景之上、植物与卡片之下**：雨雪落在草地与花盆后方，不遮文字不挡点击。
- **无 `if` 条件**：本层恒在树里（避免条件渲染让后续兄弟节点整体前移，C82 的 index 复用坑）。

## 12. 已知取舍（不是缺陷，别再当 bug 报）

| 取舍 | 理由 |
|---|---|
| todo 态底色是**青蓝**而不是「红底警示」 | 纯白雪花必须在底上可辨；警示改由红描边 + 红角标承担。红底会把雪花吃掉（两轮返工的直接原因） |
| 盾牌盒 72 但只画到 64 | 四件位图 bbox 占比差 1.7 倍，按 bbox 归一后长边统一 64 才能「视觉一样大」；盒 72 是预留 + 不参与行高的结果 |
| 盾牌盒子左侧有透明留白 | 内容贴盒右缘 ⇒ 与状态灯的**视觉**间距 = 7；左侧留白落在 chips 行右端的空白里，肉眼不可见 |
| 横飘元素只在上方 66% 活动带 | 满屏横飞观感吵；雨雪才需要落满整屏 |
| 主循环 12 分钟（不是 12s） | 只有分钟级周期才能让「最慢一档（12 分钟 1 圈）」与「最快一档（120 圈）」同时取整而不改速度量级 |
| `anyWateredToday` / `anyFertilizedToday` 保留但不用 | 拆参数要动页面 + 十余处测试，收益为零；语义上它们仍是「对话框额外提醒」的输入 |
| 温和日已购棚不显示盾牌 | 温和日没有「该搭的棚」（`shelterRefType == null`），显示会误导 |
| 动效层恒在树里（无 `if`） | 条件渲染会让后续兄弟节点整体前移，触发 C82 的 index 复用坑 |
| 光斑 / 树叶的速度档位因取整略有变化 | 偏差 ≤ 半圈 / 12 分钟，肉眼不可辨；换来接缝逐位闭合 |

## 14. 一句话给后人

> 这块的坑**全在「时间」和「可见区」两个维度上**：粒子的相位必须在 12 分钟处逐位闭合；元素的行程必须按**看得见的区域**算，并且把模糊光晕和自身尺寸算进余量。
> 二者任一破掉，肉眼看到的就是「跳一下 / 飘一半没了」——而这两种症状**长得几乎一样**，所以第一次修错了方向、复发过一次。**先跑探针，再看截图。**
