# 花园守卫 · 素材实体比记录 v1（B9 / 2026-11-10）

> 用途：把「素材透明边」这件事变成**可复算的数字**，而不是感觉。
> 玄参第四轮 iPhone 复验的两条抱怨 —— **「战士太小」+「离房子太远」** ——
> 根因都在这里：**标称尺寸 ≠ 视觉尺寸**。裁边前标称 72pt 的战士肉眼只有 ~36pt。

---

## 1. 量法（可复算）

* 判实体：`alpha > 128`（>8 会把半透明阴影算进实体，等于没裁）；
* 同组帧取**并集 bbox**（同一裁切窗口 ⇒ 播动画时实体不抖）；
* 「最大边距」= `max(left/W, top/H, (W-right)/W, (H-bottom)/H)`，**0% 表示实体贴满画布**；
* 工程护栏：`test/qa/guard_asset_solid_ratio_test.dart`（单边 ≤ **3%**）。

复算脚本（与管线同口径，PIL）：

```python
from PIL import Image

def bbox(path, thr=128):
    im = Image.open(path).convert('RGBA')
    a = im.split()[3].point(lambda v: 255 if v > thr else 0)
    return im.size, a.getbbox()      # (W,H), (l,t,r,b)

def margin(size, box):
    w, h = size
    l, t, r, b = box
    return max(l / w, t / h, (w - r) / w, (h - b) / h) * 100
```

管线：`tools/convert_guard_b5b.py`（`--force` 重跑；源目录 `assets/` 只读；
阈值 `ALPHA_THRESHOLD = 128`；WebP `q95`；长边缩到 512）。

## 3.1 战士三态**身体质心**（B11 / 第六轮真机复验）

裁到各自实体框之后，三态的**身体**在画布里的位置并不相同 —— 攻击帧的框里多了
挥出去的兵器（512 宽 vs 待机 362），`fitHeight` 居中放进来就会把身体推离中轴。
量「alpha 加权质心 x」把这件事变成数字：

复算：`python3 tools/measure_soldier_centroid.py`（`alpha > 128`，权重 = alpha 本身，
`cx = Σ(x·α)/Σα`，x 取像素中心；待机 = 19 帧 cx 的算术平均）。

| 状态 | 画布 | 质心 px | **归一化 fx** | 512 参考 | 宽高比 | 居中时身体偏移（绘制高 68） |
|---|---|---|---|---|---|---|
| idle（19 帧平均） | 362×372 | 201.23 | **0.5559** | 284.61 | 0.9731 | **+3.70pt** |
| attack | 512×349 | 225.27 | **0.4400** | 225.27 | 1.4670 | **−5.99pt** |
| win | 512×429 | 238.61 | **0.4660** | 238.61 | 1.1935 | **−2.76pt** |

> 「居中时身体偏移」= `(fx − 0.5) × 绘制宽`，绘制宽 = `68 × 宽高比`
> （66.17 / 99.76 / 81.16）。⇒ 攻击帧身体相对待机 **左移 9.68pt**，
> 正是玄参第六轮「攻击时人往左挪了一点」。
>
> **修法**：绘制时每层按 `−(fx − 0.5) × 绘制宽` 位移（`soldierStateAlignShiftX`）
> ⇒ 三态身体质心对齐 `soldierRect` 中轴；绘制高度仍以待机帧为基准（68，不缩）。
> 常量表 `kGuardSoldierStateCentroidX`；护栏 `test/guard/guard_soldier_state_align_test.dart`
> （会独立重算质心与画布尺寸，**常量过期即红**）。

## 4.2 小怪**等面积**口径（B10 / 第五轮真机复验）

玄参第五轮：「三只怪的**体量**要一样」。§4.1 的「高度齐平 44」在几何上成立，
但**面积**差了近一倍（长条的 m3 只有正方形 m2 的一半），看着仍是「一大一小」。

**口径**：面积恒定 `w × h ≡ 44² = 1936 pt²`，长宽比取**素材比例**（保留各自体型），

```
h = √(monsterArea / ratio) × scale ,   w = ratio · h        # monsterArea = 1936
```

| 怪 | 画布（裁边后） | 比例 w/h | **宽** | **高** | 面积 |
|---|---|---|---|---|---|
| m1 馋光鼠 | 512×406 | 1.261 | **49.41** | **39.18** | 1936.0 |
| m2 食叶虫 | 512×512 | 1.000 | **44.00** | **44.00** | 1936.0 |
| m3 贪婪鼬 | 512×267 | 1.918 | **60.93** | **31.77** | 1936.0 |

* 窄卡（卡宽 ≤ 380 ⇒ `scale 0.85`）：**高** 33.30 / 37.40 / 27.00，**宽** 42.00 / 37.40 / 51.79；
* 实现 `GuardCardLayout.monsterHeightOf / monsterWidthOf`（**面积 + 比例反解**，
  绝不分别写死三个宽高）；渲染仍 `BoxFit.fitHeight`；
* 🔴 **不动**：`mapMonsterX`（跑道 109.83）、`channelLeft` 的 `monsterExtent × 0.5 = 22`、纵向 ±8 窄带
  —— `monsterExtent` 语义收窄为「面积基线高度上限 / 定尺」；
* 新副作用：m3 宽 60.93 ⇒ 停下时会更明显地压住战士半个身位（长条动物的自然结果，
  主理人已在 B9.1 认可该方向）。

### 4.3 每档面积系数（B11 / 第六轮）

玄参第六轮：「馋光鼠还有点大」⇒ 给公式加一个**每档系数**（不是给某只怪开特例分支）：
面积 = `1936 × kGuardMonsterAreaFactorByKind[kind]`，再按素材比例反解。

| 怪 | 系数 | 面积 | 宽 × 高（390） | 窄卡 ×0.85 |
|---|---|---|---|---|
| m1 馋光鼠 | **0.80** | **1548.8** | **44.19 × 35.04** | 37.56 × 29.79 |
| m2 食叶虫 | 1.00 | 1936.0 | 44.00 × 44.00 | 37.40 × 37.40 |
| m3 贪婪鼬 | 1.00 | 1936.0 | 60.93 × 31.77 | 51.79 × 27.01 |

> 系数表是**唯一旋钮**（以后按单只怪微调只改它，改公式 = 三只怪一起动）；
> `mapMonsterX` / `channelLeft`（半个怪 22pt）/ 纵向 ±8 窄带零改动。
