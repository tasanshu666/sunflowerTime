# 上架注意事项 · 安卓国内渠道 v1

> **用途**：上国内各大商店（华为 / 小米 / OPPO / vivo / 应用宝）前必须处理的事项清单。
> **应用**：向日葵专注 SunFocus ｜ 包名 `com.sunflowertime.app`
> **状态**：📌 **暂不推进** —— 当前只推 App Store 海外区（见 `口径裁定表_v1.md` C69 / C72 / C73）。
> 制定：齐活林（交付总监）｜日期 2026-10-14｜**每次改动 SDK / 权限 / 隐私政策须回看本文档**。

---

## 0. 一句话结论

> **国内安卓不是「换个商店上传 APK」那么简单——它是另外三道独立门槛（备案 + 商店主体资质 + 结算对公账户），而且支付链路要整个重写。**

---

## 1. 🔴 三个结构性差异（最容易踩，且现在就影响代码）

### 1.1 Google Play 结算在中国大陆**不可用**

`in_app_purchase` 的 Android 实现（`in_app_purchase_android`）走的是 **Google Play Billing**，而国内渠道（华为 / 小米 / OPPO / vivo / 应用宝）**普遍不接受 Play 结算**。

**后果**：当前 `pubspec.yaml` 的 `in_app_purchase` 依赖**只对 iOS StoreKit 有效**。Android 版要卖东西，必须改接：

| 方案 | 说明 | 代价 |
|---|---|---|
| 微信 / 支付宝 | 国内用户最习惯，需企业主体 + 商户号 | 需服务端下单/回调校验，且**彻底放弃"权益靠商店恢复"**——必须自建账号 |
| 各商店自有支付 SDK | 华为 / 小米等各有 IAP SDK | 每个商店一套接入，维护成本高 |
| 国内聚合支付（Ping++ 等） | 一次接入多通道 | 第三方 SDK（与"无第三方 SDK"承诺冲突，需改隐私政策） |

⚠️ **最大连带影响**：一旦走第三方支付（而非商店结算），就**失去「恢复购买」的免账号基础**（不像 Apple / Google 那样能用商店账号恢复权益）→ **必须自建账号体系**才能对账与恢复。这与本项目「不做账号、不做后端」的红线**直接冲突**。
→ **因此 Android 版若要付费，等于要额外做账号 + 服务端，是一整个独立项目，不是一个 SDK 替换。**

> 💡 一个可行的折中（待玄参拍板）：**Android 版先只发免费版**（不上买断），先把口碑与用户量做起来；买断只留给 iOS。这样 Android 版不需要账号、不需要服务端，还能保住「零第三方 SDK / 纯离线」的承诺。

### 1.2 Android 版**不可能**做到「零网络权限」

实测（`flutter build apk --release` 的 merged manifest）：

| 权限 | 来源 | 是否可剥离 |
|---|---|---|
| `android.permission.INTERNET` | `billing:8.0.0` → `com.google.android.datatransport` | ❌ 剥了 Play 结算就废（国内又不能用 Play 结算 → 见 1.1） |
| `com.android.vending.BILLING` | `billing:8.0.0` | ✅ 若换第三方支付，本权限可移除 |
| `android.permission.ACCESS_NETWORK_STATE` | `just_audio` → `androidx.media3:media3-exoplayer:1.4.1` | ⚠️ 音频库附带，剥了可能伤媒体播放 |

**结论**：「零网络权限 / 完全离线」**只在 iOS 上成立**（iOS 根本没有网络权限这个概念）。**Android 版上架前，隐私政策措辞必须按平台改**，见 `隐私政策_向日葵专注_v1.md` §4 的平台差异说明。

### 1.3 App 备案主体 ≠ 现用的 Apple 个人账号

当前 Apple 用的是**个人（Individual）账号**（C72）。但：

- 🔴 **个人开发者不能办 App 备案** —— 工信部要求备案主体为**企业或个体工商户**（⚠️ 注意：个体户**可以**办，之前有说法误称个体户不行，**已更正**）。
- 备案主体须与**软著著作权人**、**各商店开发者账号主体**保持一致。
- 上国内渠道 ⇒ **必须换主体**（注册个体工商户或有限责任公司），并连带影响 Apple 账号是否要转组织。

## 2. 三道独立门槛（**备案 ≠ 上架资质 ≠ 结算资质**）

> ⚠️ 这三道是**各自独立审核**的，拿到一个**不等于**能过下一个。备案号是**必要条件，不是充分条件**。

| # | 门槛 | 要求 | 现状 |
|---|---|---|---|
| 1 | **App 备案**（工信部） | 主体为**企业或个体工商户**；个人不可办 | ❌ 未办，主体不符 |
| 2 | **软著**（全渠道强制） | 著作权人 = 营业执照主体 = 商店开发者账号主体；**APP 名称 / 软著名称 / 桌面名称必须一字不差** | ⚠️ `docs/软著材料/` 已备但**未提交**，且主体不一致 |
| 3 | **商店开发者资质** | 各商店不一（见 §3） | ❌ 主体现为个人 |

### 2.1 软著特别提醒 🔴

- ⚠️ **2026-03-15 起，软著申请表新增「未使用 AI 开发」手写承诺**。本项目**大量 AI 辅助开发**，须提前评估如何填写（**法律问题，建议单独咨询**）。玄参已表示不关注此风险，此处仅记录。
- 软著名称要与商店展示名、App 内名称**完全一致**，改名要重办软著。

## 3. 各商店主体资质要求对照

| 商店 | 接受个人？ | 接受个体工商户？ | 备注 |
|---|---|---|---|
| 华为 | 相对宽松（部分来源称支持个人） | 部分来源称接受 | ⚠️ 待向官方核实 |
| 小米 | 多数来源称认企业营业执照 | 部分来源称接受 | ⚠️ 待向官方核实 |
| OPPO | — | ✅ 明确接受「企业营业执照**或**个体工商户营业执照」 | 来源较明确 |
| vivo | 多数来源称认企业 | 部分来源称接受 | ⚠️ 待向官方核实 |
| 应用宝（腾讯） | 多数来源称认企业 | 部分来源称接受 | ⚠️ 待向官方核实 |

⚠️⚠️ **付费 / 内购类 App 对个体户可能受限**：有代办机构称「个体户仅允许极简免费工具，社交 / 商城 / 付费类直接拒审」。**本项目含内购 → 风险较高，且政策在收紧。**
→ **稳妥路径 = 注册有限责任公司**（一步到位同时解锁：App 备案 + 国内安卓渠道 + Apple 组织账号 + 主体一致）。

## 4. 结算与合规

| 项 | 要求 |
|---|---|
| 结算账户 | 需**对公账户**（个体户也需开） |
| 儿童类合规 | 国内对儿童个人信息更严（实名、防沉迷、家长同意）；本项目数据全在本地、无账号，**合规压力天然较低**，但商店可能仍要隐私政策与合规声明 |
| 广告 | 玄参明确**不做广告**——可省掉广告 SDK 与相关合规，但商店可能对免费无广告 App 有单独分类 |

## 5. 上架前 Checklist（按序）

- [ ] **主体决策**：注册个体工商户 or 有限责任公司（**建议有限责任公司**）
- [ ] **软著提交**：名称锁定为「向日葵专注」（与商店名、App 内名一致）；评估 AI 声明
- [ ] **App 备案**：工信部备案，主体与软著一致
- [ ] **商店开发者账号**：逐平台注册，营业执照 + 法人身份证 + 对公账户
- [ ] **支付方案决策**：见 §1.1 —— 是否接受「Android 版先只发免费版」
- [ ] **隐私政策按平台改措辞**：Android 版必须说明 INTERNET / BILLING（或第三方支付 SDK）的存在与用途
- [ ] **权限复核**：若放弃 Play 结算，移除 `com.android.vending.BILLING` 与相关依赖
- [ ] **商店截图**：华为 / 小米 / OPPO / vivo / 应用宝各一套（见 `商店文案_国内安卓_v1.md`、`商店截图清单.md`）
- [ ] **隐私政策公网 URL**：必须是**可访问的公网地址**（当前仍是占位）

## 6. 待核实项（**不要凭本清单直接决策**）

1. 各商店对**个体工商户 + 内购类 App** 的最新政策（政策在收紧，务必开店前致电官方或查最新开放平台文档）。
2. Apple **组织账号是否接受个体工商户**——来源矛盾：官方《D-U-N-S》帮助页只写「不接受 DBA、虚构企业、营业名称或分公司」，**未直接点名个体工商户**；有来源称个体户即使拿到 D-U-N-S 也会被拒。**须向 Apple 官方确认。**
3. 软著 AI 声明的具体填写口径（建议咨询代理或法务）。
4. 若走第三方支付，各商店是否允许（部分商店要求**必须**用其自有支付 SDK）。
