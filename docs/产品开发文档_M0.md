## 1. M0 的产品定位

M0 不是给孩子的功能版本，而是**把后续所有功能能装上去的"壳"**：

| 交付面 | 对孩子/家长是否可感知 | 说明 |
|---|---|---|
| 加密本地库（Drift + SQLCipher） | ❌ 不可感知 | 数据底座，C13 合规要求 |
| 竖横屏与导航骨架 | ✅ 可感知 | 孩子端竖屏、打盹屏横屏、家长端独立入口 |
| 家长 PIN 锁 | ✅ 可感知 | 家长端与孩子端隔离 |
| 首启同意流 | ✅ 可感知 | G0 合规落地 |
| 参数单点 | ❌ 不可感知 | 防数值孪生，后续里程碑的公共地基 |

## 2. 用户可感知的完整路径（M0 实测路径）

```
首次启动
  └─ 同意流页（ConsentPage）
        └─ 点「同意并开始」→ 孩子端首页（竖屏）
              ├─「进入打盹屏（S3）」→ 横屏打盹屏
              │      ├─ 倒计时（本次 mm:ss / 总 mm:ss）+ 剩余小字（调试用）
              │      ├─ 中央向日葵（呼吸式明暗，零突事件）
              │      ├─ 常亮保持（真机验证 20 分钟未被省电策略杀）
              │      ├─ 物理竖屏 → 暂停 + 「确定结束吗？」
              │      ├─ 系统返回键 → 同上（手动退出，架构 §1.3）
              │      └─ 结束 → 回孩子端首页
              ├─「四档反馈预览（S1）」→ 四档切换 + AppBar 返回
              └─「家长天地 →」→ PIN 页
                    ├─ 首次：设置并进入
                    ├─ 再次：校验 PIN（错则提示「PIN 不正确」）
                    └─ 家长端首页 → 返回箭头 / 系统返回键 → 回孩子端
```

## 3. 已实现的交互规则（依据现有文档，非新决策）

| 规则 | 依据 |
|---|---|
| 打盹屏**本屏不可交互**（无任何可点控件） | PRD §4.1 |
| 退出路径写死：**竖屏确认** → 确认框「确定结束吗？（再坐一会 / 结束）」 | PRD §4.1.6、验证计划 §4.2「退出路径写死（竖屏确认/无操作区/回归首帧欢迎）」 |
| **系统返回键 = 手动退出**，与物理竖屏同路（暂停 + 确认） | 架构 §1.3「竖屏动作（物理竖屏 **OR 手动退出**）→ 触发暂停+确认」 |
| 竖屏期间**不计入**专注时长；「再坐一会」从暂停处续上 | PRD 专注计时口径（C3） |
| 灭屏期间**仍在计时**（打盹语义：孩子睡着也算专注），恢复后不漂移 | 墙钟差设计；真机已验证 |
| 家长端与孩子端**物理隔离**（PIN 进入，退出即回孩子端） | 架构 §4.9 / §10.4 |
| 首启未同意 → 强制同意流，不可绕过 | G0 合规、验证计划 |

## 5. M0 已确认的体验结论

1. **打盹屏常亮可用**：横屏放置连跑 20 分钟未被国产 ROM 省电策略杀掉（缓解架构 P6 风险，多机型仍待补测）。
2. **计时不受灭屏影响**：灭屏期间照常计时，恢复后无漂移。
3. **方向判定已可用**：竖握进入不误触发；先横屏放置、再转竖屏才会弹确认框。
4. **家长端隔离成立**：PIN 双态（首次设置 / 后续校验）行为正确。

## 6. 交接给 M1 的事项

> 仅列 M0 边界内的欠账，不涉及新的产品规划。

| # | 事项 | 原因 |
|---|---|---|
| 1 | 7 个 Repository 中 5 个为桩（Focus/Task/Plant/Reward/Tracking） | M0 只做骨架与装配 |

| 5 | 实体未切 freezed | M0 规避 codegen 风险，M1 可切 |
| 6 | 打盹屏常亮仅单机型验证 | 架构 P6 建议 3–5 台（含低端旧机）连跑 30–60min |
