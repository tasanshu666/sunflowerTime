## 0. 一句话结论（含与主理人背景判断的冲突）

**§9「条幅 overlay + 三态 + 完成态」实际上没有作为「条幅」被实现。** 当前花园页顶部的那条天气面，是 A2 期交付的**薄天气行**（`GardenWeatherRow`：胶囊 28 / 槽 32 / 命中 44 高，常驻、9 种日型恒在）+ **道具购买按钮的三态**（可买金 / 已购绿+✓ / 余额不足灰）+ **买棚瞬间 toast（§9.6）**。§9 要求的 **56pt 白色半透明条幅、todo/done 文案、👍 完成态、点条幅→帮助段** 均**未实现**。

**与主理人背景判断的冲突（先指出）**：背景说「A3 只做过一件：FD1（commit 417ac10）」。核对后——**FD1 是 `weather_status_bar` 胶囊提示语被 ellipsis 截断的 bug 修复**（`test/m3/weather_a2_test.dart:1932-1977` 的守卫块自述「A3 首件」），它修的是 **A2 薄行组件**，**不是 §9 条幅**。因此更准确的说法是：

- **A3 真正落地过的只有**：§9.6 买棚 toast（A2 交付时随购买流程一并做了）+ FD1（薄行缺陷修复，被记为「A3 首件」）。
- **§9 条幅主体（overlay / 三态 / 完成态 / 可点→帮助）从未开工。**

这与「A3 = 条幅 overlay + 三态 + 完成态」的定义**一致（确未开始）**，仅「A3 只做过一件 = FD1」这一表述需要修正（FD1 是薄行缺陷，不是条幅功能）。团队自存记忆亦如此登记：`.workbuddy/memory/MEMORY.md:9` 与 `2026-11-03.md:258-261` 的「待 A3」只列 **FD1（已 done）/ 平板不齐边 1.8pt / M-G 平板覆盖缺口**，从未提及条幅。

## 2. Q2 · 「平板不齐边 1.8pt」到底是什么

**证据位置**：`test/m3/weather_a2_test.dart:1907-1910`（M-G 注释块的「🔎 实测佐证（TEMP probe @ 834×1194，第 4 轮）」）。

- **哪个元素对哪个元素差 1.8pt**：**天气行内胶囊的视觉顶** vs **左端 chips 的视觉顶**。
  - chips 顶 = **12.0**；天气（胶囊）顶 = **13.8**（scale=1.3 时）⇒ 差 **1.8pt** 不齐边。
- **常量链（根因）**：
  - chips 的 `Padding(top: 6)` 是**固定字面量 6**（不乘 `s`）⇒ chips 顶 = 行容器顶(6) + 6 = **12.0**，不随倍率变。
  - 天气行内垂直居中偏移 `(44−32)/2 = 6` **乘了 `s`** ⇒ 胶囊顶 = 行容器顶(6) + `6×s`；`s=1.3` ⇒ 6 + 7.8 = **13.8**。
  - `s=1`（手机）时两者都 = 12.0 ⇒ **手机零回归**；仅平板浮出 1.8pt。
  - 公式：差 = `6×(s−1)`；`s=1.3 ⇒ 1.8pt`，`s=1.6 ⇒ 3.6pt`（与 A2 §7-K27 `12(s−1)` 的「固定 vs 乘倍率」同源问题，但此处是**顶对齐偏移**而非高度差）。
- **定性 = 已登记 · 未修 · 待裁定**：测试注释明写「此不齐边是否需修，由主理人 / 架构师裁定；本测试**不**就此断言」（`test:1909-1910`），且 M-G 组只锁手机档。倾向「**登记不改**」——与 A2 已封版的 §7-K27 / R24「平板承认不同高、差异 = `12(s−1)`、登记不改」同一处置口径（**此为倾向，非既成裁定**）。

## 3. Q3 · 「M-G 平板覆盖缺口」到底是什么

**证据位置**：`test/m3/weather_a2_test.dart:1894-1930`（`// M-G · 平板档 UI 层守卫`）。

- **M-G 是哪条变异**：A2 第 4 轮 QA 的变异验证 M-A~M-G 中的第 7 条，主题 = **平板档 UI 层守卫**（不是纯函数层）。
- **缺哪一档视口的断言**：缺 **平板视口（834→1.3 / 1032→1.6）下 pump UI 层** 的渲染断言。现有唯一测试 `M-G · 手机视口（390×844）…`（`test:1912-1930`）只断言「手机档 `uiScaleOf == 1.0` 不被回归」，**从未在平板视口 pump 过 UI 层**。
- **生产代码是好的**：`weather_status_bar.dart:1103` `uiScaleOf(context)` 是**视口驱动**（`9xx`：短边<600⇒1.0，834⇒1.3，1032⇒1.6 钳制）；平板档**走得到**。缺口纯在**测试覆盖**——平板档（1.3/1.6）的 UI 表现（含上面 1.8pt 不齐边）无自动化保护。
- **定性 = 已知覆盖缺口（登记，不是失败断言）**；`test:1902-1905` 明写「平板档缺口就登记在这里，不靠改 `lib/`（`uiScaleOf`/`responsive.dart`）来凑绿」。
