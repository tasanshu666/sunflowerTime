### 0.2 用户反馈原文（逐字收录，唯一立意来源）

> 以下 4 条 + 结语为玄参真机反馈**逐字原文**（比对时去掉 markdown 强调符）。本文档所有需求均可追溯至此，不新增机制。

**1、许愿树的入口放在右上角天气的下面；**

**2、进入许愿树页面后，这是一个单独的页面，不应该在听见花园的背景音乐，现在还是能听见花园的背景音乐，需要修复一下。**

**3、我认为这是孩子自己许的愿望，这个愿望不一定需要爸爸妈妈设定目标或者计划如何实现，所以我认为，应该有一个按钮，让孩子自己选择是否推送给爸爸妈妈，请爸爸妈妈帮助实现，推送了之后，才到家长端看见，并给出回应，如果没有推送，家长也不必知道，就让孩子自己决策即可。即使永远的挂在树上，也是他的记忆。**

**4、在家长端，对孩子的愿望，选择贴标签选项后，再选择取消按钮，则无响应，点击其他空白地方后，直接退出了家长空间，需要修复。@截图：贴标签弹层里「选一个标签（可以跳过）/取消」整组出现两次、「预设回复」标题出现两次。**

**"先修复上述问题。"**

### 0.3 反馈拆分与归类

|---|---|---|---|

## 1. 产品定义

### 1.1 产品目标（3 个正交目标）

| # | 目标 | 可度量结果 |
|---|---|---|
| G1 | **孩子自主权**：愿望是否让爸妈知道由孩子决定；未授权时家长端不可见，但愿望完整保留为孩子记忆 | 未授权愿望在家长端查询结果为 0 条；盖章计数不变；树上展示不变 |
| G2 | **场景纯净**：许愿树为独立音频场景，进入停播花园环境音、退出恢复 | 进入后 `_ambientPlayer.isPlaying == false`；返回花园后恢复播放 |
| G3 | **交互可靠**：入口可达、弹层与返回栈行为确定 | 天气下方入口可点击进树；弹层标题唯一；取消/点遮罩均不离开家长空间 |

三目标正交：G1 数据可见性、G2 音频生命周期、G3 UI/导航健壮性，互不耦合。

### 1.2 用户故事

| # | 用户故事 |
|---|---|
| US1 | As a 孩子, I want 在花园右上角天气下面直接点进许愿树, so that 不用绕到左侧木牌或翻到今日页底部。 |
| US2 | As a 孩子, I want 自己决定要不要把愿望告诉爸爸妈妈, so that 有些小心愿可以只属于我自己。 |
| US3 | As a 孩子, I want 点亮「告诉爸爸妈妈」后愿望才出现在家长端, so that 我真正掌握分享的主动权。 |
| US4 | As a 家长, I want 只看到孩子愿意分享的愿望并贴标签/回应, so that 我的回应建立在孩子允许的基础上。 |
| US5 | As a 家长, I want 在贴标签弹层点「取消」能稳定留在家长空间, so that 我不会因误触被踢出。 |

## 2. 需求池

### 2.1 状态机：孩子自主推送开关（R-P0-01 的权威定义）

| 项 | 定义 |
|---|---|
| 存储 | `Wishes` 表新增 1 列本地标记 `sharedToParent`（INTEGER，默认 `0`），**schemaVersion 32 → 33** |
| 语义 | `0` = 未推送（家长不可见）；`1` = 已推送（家长可见）。**仅本地可见性标记，无联网、无账号、无系统通知** |
| 触发 | 孩子端愿望卡上的「告诉爸爸妈妈」按钮，点亮即写 `1`（可附点亮时间戳，由架构师定） |
| 独立性 | 该列**不参与** `status` 六态迁移、**不影响**盖章计数、**不影响**树上挂载与收藏箱行为 |

| 当前态 | 事件 | 下一态 | 副作用 |
|---|---|---|---|
| 未推送(0, 默认) | 孩子点亮「告诉爸爸妈妈」 | 已推送(1) | 写入标记；家长端 `parentDeskList()` 开始返回该愿望 |
| 已推送(1) | 家长贴标签 / 写回应 | 已推送(1) | 状态不变；回信写入既有字段 |
| 已推送(1) | 孩子点撤回（**Q1 待拍板**） | 推荐：未推送(0) | 家长端隐藏；已写回应的处置见 Q1 |
| 任意 | `fulfill`/`abandon`/`replace`/`releasedAt` 变化 | 状态机照旧 | 可见性标记原样保留，不随状态复位 |
