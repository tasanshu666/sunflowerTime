## 1. 产品目标（一句话）

> **把孩子「看不见的累计专注时长」翻译成一套「等级多（几乎每次专注都有进度）+ 称号少（稀有、有仪式感）」的荣誉体系，让孩子在今日页一眼看到自己「专注了多久、现在是什么称号、下一个称号还差多少」。**

三条正交目标：

| # | 目标 | 判据（可度量） |
|---|---|---|
| G1 | **成效可见**：累计专注时长 → 等级 + 称号，进今日页即可见 | 今日页可见等级徽章与称号；未达 Lv.1 也有明确引导（§4.4）；老用户首次进入**直接**拿到应得等级 |
| G2 | **里程碑稀有而有仪式感**：只在 9 个称号节点发阳光（演出则每次升级都播） | 9 个节点共 **102 ☀**；31 次普通升级**零阳光、零账本行**（但**照播 default 演出**）；同一节点**绝不重复发放** |
| G3 | **纯荣誉、零副作用**：不干扰既有经济与玩法节奏 | 等级不进入成长速度 / 产量 / 防沉迷 / 专注产光的任何计算（以调用图断言锁定，见 AC-11） |

## 4. 等级与称号

### 4.1 判定口径

- **驱动量** = 累计**有效专注分钟**（从 App **首次使用**开始累计，**不是**从本功能上线起算）。
- 与 C39「到时判定切专注时长口径」同源：`actualFocusMin` **只累计 running**，离席 / 暂停不计。
- **短会话（< 5 分钟）计入**累计（玄参 2026-10-14 拍板 ③，与结算页里程碑 600 分钟口径一致，不另设门槛）。
- 判定规则：**`累计分钟 >= 门槛` 即达到该等级**（闭区间下界），取满足条件的最大等级。
- 🔴 **允许跳级**：老用户一上线直接拿到应得等级（C74 §1）。
- 🔴 **存在「未达 Lv.1」状态**：Lv.1 门槛 = **60 分钟**（不是 0），累计 < 60 分钟时 `level = 0`、无称号（见 §4.4）。这是**新用户头几天会一直看到的状态**，UI 必须给出正向引导文案。

## 5. 阳光发放规则

### 5.1 只在 9 个称号节点发（总计 102 ☀）

| Lv.1 | Lv.5 | Lv.10 | Lv.15 | Lv.20 | Lv.25 | Lv.30 | Lv.35 | Lv.40 |
|---|---|---|---|---|---|---|---|---|
| +3 | +5 | +7 | +9 | +11 | +13 | +16 | +18 | +20 |

- 合计 **102 ☀**（= 3+5+7+9+11+13+16+18+20）。
- 🔑 **关键规则**：**40 级里的另外 31 次普通升级零阳光、零账本行**，只更新徽章进度 —— 把阳光注入量压到最小。（⚠️ 演出层已于 2026-10-14 晚改为**每次升级都播**，普通升级播 `defaultLevelUp` 素材 + `default_level_up.mp3`，**不产出任何阳光**，见 §7.1。）
- 未解锁态（`level = 0`）不发阳光；跨到 Lv.1 是第一次发放（+3）。
- 与专注产出**互不影响**：本表是独立的一次性发放，不占用年段日专注上限（60/90/120 分钟）、不占用成长奖励日上限（80 ☀，C94 于 2026-10-19 由 79 取整为 80）、不占用周池。

### 5.2 发放时机

| 项 | 口径 |
|---|---|
| 触发点 | **孩子进入「今日页」时**（含：首次挂载 / 切回今日 tab / App 回前台且今日页可见 —— 已由 C68 `ChildTabAutoRefresh` 覆盖） |
| 判定 | `currentLevel（由累计分钟算出） > settledLevel（已结算到的最高等级）` → 有待结算的升级；其中**只有跨过的称号节点**（Lv.1/5/10/15/20/25/30/35/40）**才发阳光**；**演出则每次升级都播**（🔴 2026-10-14 晚修订，普通升级也播 default 素材，见 §6.6 D / §7.1） |
| 发放顺序 | **先写账本、后播演出**（阳光先落袋；演出被中断/杀进程不回滚、不重播，账本为事实源） |
| 🔴 禁止 | **不接受「结算页当场播」**（C74 §6）；结算页不得引用等级 / 演出组件（AC-07） |
| 跳级处理 | 一次跨 N 级 → **逐条入账**（每个**跨过的称号节点**一条账本行，各按本阶梯金额），**演出只播 1 场**（显示**最高级称号**），跨过多级时文案含「连升 N 个称号！」 |
| 首用 | 老用户首次进入：**只认等级与称号、不发阳光、不播演出、不弹任何欢迎卡**（静默升级，玄参 2026-10-14 拍板 ②；见 §8.2） |

### 5.3 幂等红线（🔴 硬要求）

- **同一称号节点绝不重复发放**（C74 §4）。
- 幂等锚点 = **双锚点取大**：
  1. **阳光账本**：`refType = 'focus_level_up'`（值一经写入即**冻结**，append-only）+ `refId = 'lv{n}'`（如 `'lv10'`，小写、无空格）→ 发放前判据 `countByRefTypeAndRefId('focus_level_up','lv{n}') == 0` 才写；
  2. **SharedPreferences** 键 `focus_level_settled`（语义 = **已结算到的最高等级**，不是「首用基线」）→ 不升 `schemaVersion`（当前 **24**），与 C14 防沉迷同款先例。
- 写账本失败**不重试**（append-only，重试只会产生重复行；与护眼 `_appendReward` 同纪律），跳过该条继续。

### 7.4 演出时序（进入今日页）

```
_reload()
  ├─ totalMinutes ← FocusRepository.totalStats().totalFocusMinutes
  ├─ currentLevel ← levelOfMinutes(totalMinutes)      // <60 分钟 → 0（未解锁）
  ├─ settledLevel ← max(SP 'focus_level_settled', 账本派生的已发最高等级)
  └─ if (currentLevel > settledLevel):
       nodes ← 区间 (settledLevel, currentLevel] 内跨过的称号节点 ∈ {1,5,10,15,20,25,30,35,40}
       ① 逐条发阳光（只发 nodes）：
            for n in nodes:
              若 countByRefTypeAndRefId('focus_level_up','lv{n}') == 0
                → append(SunlightEntry(type: earn, gross=net=节点金额,
                                       balanceAfter=before+amount,
                                       refType:'focus_level_up', refId:'lv{n}', dayKey))
              写失败 → 跳过、不重试
       ② 更新 SP 'focus_level_settled' = currentLevel
       ③ economyRevisionProvider 自增（今日阳光 / 我的页同步刷新）
       ④ 页面可见 → 播 1 场 LevelUpFxOverlay（**普通升级也播**）：
            素材/音效 = (最高新等级 ∈ 称号节点) ? 5leveUp + 5_level_up.mp3
                                                 : defaultLevelUp + default_level_up.mp3
            文案 = 称号节点：最高级称号 + 本轮合计阳光 (+N ☀) +（跨多级时）「连升 N 个称号！」
                  普通升级：新等级 + 距下一称号节点的进度（无阳光段）
          nodes 为空时本场演出**不写任何账本行、不发阳光**（纯视觉）
          不可见 → 不播（等级已结算，下次进页显示新等级，不补播）
  └─ else: 不播、不发
```

- **首用判定**：账本 `countByRefType('focus_level_up') == 0` 且 SP 无 `focus_level_settled` ⇒ 首次进入本功能 ⇒ 写 `focus_level_settled = currentLevel`，**不发阳光、不播演出、不弹任何卡**（静默升级，§8.2）。

## 8. 数据口径与边界

### 8.1 「累计有效专注分钟」现有数据在哪（读码实证）

| 层 | 位置 | 字段/对象 |
|---|---|---|
| Drift 表 | `lib/data/local/database/tables.dart:155` | `FocusSessions.actualFocusMin`（列名 **`actual_focus_min`**，REAL） |
| 领域实体 | `lib/domain/entities/focus_session.dart:9` | `FocusSession.actualFocusMin` |
| 聚合实现 | `lib/data/local/repositories/focus_local_repository.dart:73` | `FocusLocalRepository.totalStats()`：全表取行 → `totalMinutes += r.actualFocusMin`（**内存求和**；`_isValidSession` 只用于「有效专注日」统计，**不用于分钟求和**） |
| 聚合结果 | `lib/domain/entities/focus_stats.dart:11` | **`FocusStats.totalFocusMinutes`**（= 全部会话 `actualFocusMin` 之和） |
| 接口 | `lib/domain/repositories/focus_repository.dart:11` | `Future<FocusStats> totalStats()` |
| 现有消费方 | `child_profile_page.dart:103/118/194`、`settle_page.dart:309-314`（里程碑 600 分钟） | 「累计专注时长」卡 / 纪念册里程碑埋点 |

**结论**：✅ **已有可直接累计的字段，无需新增表/列** —— 等级驱动量 = `FocusStats.totalFocusMinutes`（现有实现），无需 `GROUP BY`、无需新列。

- 口径细化（**已拍板**）：`totalStats()` 把**所有会话**的分钟计入，含 `shortAborted`（< 5 分钟、产出 0）的场次 —— 玄参 2026-10-14 拍板 ③「短会话计入」，与结算页里程碑 600 分钟口径一致，**不另设门槛**。

### 8.2 老用户首次进入（静默升级）

- 直接调 `totalStats()` → `currentLevel`，**立即显示应得等级与称号**（允许跳级）。
- 🔴 **不补发历史称号节点阳光**（只发「进入后新达成」的节点）。例：老用户累计 5000 分钟 → **Lv.18**（80h=4800 ≤ 5000 < 5340=89h）、称号「时光小卫士」（最高已解锁节点 Lv.15）→ 账本 **0 条**、不播演出。
- 判定与持久化：账本 `countByRefType('focus_level_up') == 0` 且 SP 无 `focus_level_settled` ⇒ 首次进入 ⇒ 写 **`focus_level_settled = currentLevel`**。
- 存储：**SharedPreferences**（键 `focus_level_settled`，落 `core/constants/app_constants.dart`，与防沉迷 `kPrefAppUsageDate` 同处，**语义 = 已结算到的最高等级**）→ **不升 `schemaVersion`**（维持 24），与 C14 防沉迷同款先例（C74 §8）。
- 🔴 首用**不播演出、不弹欢迎卡**（玄参拍板 ② 静默升级）。

### 8.3 重装 / 换设备 / 清除数据

| 场景 | 行为 | 依据 |
|---|---|---|
| 卸载重装 / 换设备 | 单机无账号、无云端 → 库空 + SP 空 = **新用户**：`level = 0`（未解锁态），**不补发** | C1 单机版口径 |
| 家长端「一键删除全部本地数据」 | Drift 全表 + 安全区 PIN + **SharedPreferences 全部键**一并清（`data_management_service.dart:31`）→ 同上 | 现有实现已覆盖 SP |
| SP 丢失、账本仍在 | 以账本为准（账本有 `focus_level_up` 行 ⇒ 已过首用），**不受影响** | 账本即事实源（C12） |
| 账本与 SP 都无、但会话累计 > 0 | 按「老用户首用」处理：认等级与称号、**不补发** | §8.2 |
| 时钟回拨 | 等级只由累计分钟派生（单调不减）；已发行不撤销、不回退 | 与 `shouldRefreshForTimeBoundary` 同纪律 |

### 8.4 阳光账本怎么记

| 项 | 口径 |
|---|---|
| 事实源 | **`sunlight_ledger` 表**（C12 / C74 §9） |
| 🔴 禁止 | **不给任何实体表加计数列**（不新增 `focus_level` 列）；等级与已发等级全部由「会话聚合 + 账本计数 + SP」派生，**`schemaVersion` 维持 24** |
| 新增 refType | **`focus_level_up`**（字符串值**冻结**，append-only；改名只能改常量名不改值） |
