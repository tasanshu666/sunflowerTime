## 1. 信息架构改动（玄参拍板 = 候选 A）

### 1.1 记录 tab 的分段结构与职责边界

现状：`ParentHistoryPage`（`parent_history_page.dart:53`）自带 `_Period{day,week,month}`（:36-50）+ `_PeriodBar`/`_PeriodNav`（:419-512），承载**成长任务完成记录 + 奖励兑换记录**两块（:208-235）；作为「记录」tab 内嵌页（无 Scaffold/AppBar，:18-19）；tab 定义在 `parent_home_page.dart:101-105`（`Icons.history` + label「记录」）。

改造后：

```
ParentHistoryPage（顶层：只做「分段切换 + 渲染当前段」，无 Scaffold/AppBar）
 ├─ 分段控件（SegmentedButton，默认 index=0「专注报告」）
 ├─ [seg=报告] FocusReportSection    ← 新：自有 period{日/周/月/年} + anchor + future
 └─ [seg=记录] HistoryActivitySection ← 由现有记录内容「整体抽出」保自有 period{日/周/月}+anchor+future
```

**两段期间是否联动 → 建议各自独立。理由（三条，硬性）：**
1. **粒度集合不同**：记录段 `_Period{day,week,month}`，报告段需 `{day,week,month,year}`。任何「联动」都会在记录段产生**非法粒度 year**（无对应 `_startOf/_endOf/_prevOrNext` 分支 → `switch` 不穷尽 / 运行期缺省）。
2. **语义不同**：记录段 = 任务/兑换「事实计数」；报告段 = 专注「时长聚合」。同一锚点跨段无业务含义。
3. **交互不同**：记录段锚点=「日」时切到报告段，若联动会强把报告也锁在「日」，家长想看年报得重新翻——违背 G2「四档随手切」。

→ 因此**提炼共享组件**（`ReportPeriodBar` 日/周/月/年、`PeriodNav` ◀▶ 可复用记录页范式），但**状态各自持有**。

### 1.2 入口路径（家长端 tab → 分段）

- 家长端底部任意 tab →「记录」（1 click）→ 默认即专注报告段（**0 额外 click**）⇒ 满足 G1「≤1 次点击」。
- 分段控件在页面顶部（Scroll 之上，常驻）；「任务与奖励」为第 2 段（1 click 可达，记录功能不退化）。

### 1.3 设置页原入口如何处置 → **建议「保留 + 重定向」，不删除**

现状：`parent_settings_page.dart:392-397` 一张入口卡「专注报告」`onTap: context.push('/parent/report')`。
- **删除**风险：家长在「数据入口」区找数据的心智模型被打断（以为功能没了）。
- **建议**：入口卡保留，`onTap` 改为 `context.go('/parent/home?tab=history&seg=report')`，并在 `ParentHomePage` 支持 `initialTab`/`initialSegment` 参数（`app_router.dart` 的 `/parent/home` builder 读 `state.uri.queryParameters`）。旧 `/parent/report` 路由**保留重定向**到同一目标（兼容历史深链）。

## 2. 数据层方案

### 2.1 周期口径（半开区间 `[start, end)`，全部纯本地派生）

| 周期 | `start`（含） | `end`（不含） | 与现状口径 |
|---|---|---|---|
| 日 | 当日 00:00 | +1 天 | 记录页 `_startOf/_endOf`（`:106-127`）|
| 周 | 本周一 00:00 | +7 天 | 周一起始（`datetime_ext._mondayOf:17-20`；记录页 `anchor.weekday-1`）｜沿用 C55 |
| 月 | 当月 1 日 00:00 | 次月 1 日 00:00 | 自然月 ✅ |
| 年 | 当年 1 月 1 日 00:00 | 次年 1 月 1 日 00:00 | 自然年 ✅ |

- 不翻未来：`end <= now` 才可 ▶（同记录页 `canNext`，`:188`）。
- **⚠️ 防孪生（第 3 处）**：周起始现有两处各算一遍（`datetime_ext._mondayOf` 私有 + 记录页自写）。本批**提炼 `datetime_ext.dart` 纯函数** `startOfDay/startOfWeek/startOfMonth/startOfYear` + `endOf(period)`，三处统一引用。
- 有效专注日判定**不新造**：沿用 `focus_report_service.dart:111-117` 的 `_isWfd`（`actualFocusMin ≥ kValidFocusMinutes` 且完成率 ≥ `kCompletionRateThreshold`）。

### 2.2 月 / 年聚合（怎么算）

- 取区间内**逐日** `DailyFocusPoint`（`dayKey/date/focusMinutes/sessionCount/isWfd`，复用 `focus_report_service.dart:15-29`）。
- 派生指标（**事实源 = 专注会话表，绝不给实体表加计数列**）：
  - 累计分钟 = Σ`focusMinutes`；有效专注日数 = `count(isWfd)`；
  - 平均每日 = 累计分钟 / 天数（⚠️ 分母口径见 §6-DR3）；最好的一天 = `max(focusMinutes)` 及其日期；
  - 年：12 个月趋势（按月分组求和）+ 最长连续有效专注日（单次扫描）。
- 取数方式见 §2.3（范围查询）。

### 2.3 §6-⑥ 结论：给 `FocusRepository` 加方法？→ **不加；新增独立能力接口**

**实测证据（决定本结论）**：
- `FocusRepository` 现仅 4 个方法、**无范围查询**（`focus_repository.dart:5-12`）。
- `focus_sessions` 表**仅 PK=id，`start` 无索引**（`tables.dart:150-162`）；`schemaVersion == 24`（`app_database.dart:59`）。
- `implements/extends FocusRepository` 的**实现 + 测试桩实测 51 处**（49 个测试文件共 50 个桩 + 1 真实现；`grep` 实测）——给本体加「带默认实现的方法」在本仓 Dart `implements` 语义下**实现类仍须显式实现**，必致全量编译失败（历史坑：45 fake；`task_repository.dart:17-23` 已把此坑写成注释纪律）。

**① 逐日组合够不够？** 年热力图 = 最多 366 次 `sessionsOfDay`。数据量级小（单机单孩子 ≈ 数百~千行）、Drift 走 FFI（非 platform channel），**总量不炸**；但 **366 次串行 `await` + 每次字符串解析/建 query** 会拉长首帧（低端安卓尤甚），且是 366 行循环，可读性/可测性差。**可行但不体面。**

**② 若必须新增查询能力 → 采用「独立能力接口」（本仓既有纪律）**：

```dart
// lib/domain/repositories/focus_repository.dart（新增，不动 FocusRepository 本体）
/// 专注会话「范围查询」能力接口（报告热力图 / 年聚合用）。
/// 与 FocusRepository 刻意分离：直接给本体加方法会牵动全部 implements（实测 ≈49 处）。
abstract class FocusRangeQuery {
  /// 半开区间 [from, to) 内的全部会话，按 start 升序。
  Future<List<FocusSession>> sessionsBetween(DateTime from, DateTime to);
}
```
- 真实现：`FocusLocalRepository implements FocusRepository, FocusRangeQuery`（一次范围 `SELECT`）。
- 消费：`FocusReportService` **能力探测** `if (_focus is FocusRangeQuery)` → 1 次查询后在 Dart 内按日聚合；`else` → 回退逐日 `sessionsOfDay`（**既有 ~49 个 fake 不实现新接口 → 自动走回退，编译零影响**）。
- **需同步的只有**：① `FocusLocalRepository`（+implements + 方法）；② `FocusReportService`（新增按周期构建方法）；③ **新写的报告测试**（新增一个 `implements FocusRangeQuery` 的 fake 验证快路径；复用旧 fake 验证回退路径）。

**③ 推荐 = 独立能力接口**。收益（1 次查询 / 可读 / 可测）× 成本（仅真仓储 + 新测试，**0 既有 fake 改动**）明显优于逐日；与本仓纪律「给仓储加方法优先建独立能力接口」（`task_repository.dart:17-23`）一致。

**不改表 / `schemaVersion` 维持 24**：范围查询只用既有列 `start/plannedMin/actualFocusMin`，**无新表 / 无新列 / 无迁移**。

## 3. UI 结构

### 3.1 报告段（`FocusReportSection`，自上而下）

1. **周期切换器** 日 / 周 / 月 / 年（4 档）+ ◀ 期间 ▶（不翻未来，▶ 到顶禁用）——复用记录页 `_PeriodBar`/`_PeriodNav` 范式。
2. **Hero 主指标卡**：本期累计专注分钟（大字）+ 副指标（有效专注日 / 平均每日）。
3. **趋势图**：日/周 → 7 日柱（复用现有 `_WeekChartCard` 形态，`parent_report_page.dart:498`）；月 → 按周分组的 4~5 根柱（⚠️ 形态见 DR4）；年 → **12 个月柱**。
4. **热力图**（`deepReport`）：近 1 年日历热力图，**行=周一~周日、列=周**；色阶 **4~5 档**（0 / 1–14 / 15–29 / 30–59 / ≥60 分钟）；图例 + 「当前连续 N 天 / 最长 N 天」读数；点格 → 轻提示该日分钟。
5. **护眼统计卡**（P2，可随周期过滤；现有 `_EyeCareCard`，`parent_report_page.dart:230`）。
6. **环比对比**（P1，本期 vs 上期）。

深色模式：沿用现有 `_ReportPalette`（浅/深两套，`parent_report_page.dart:29-95`）。

### 3.2 免费 / 付费可见性规则表（**逐档列清 — 门控接线依据**）

免费边界（玄参拍板）：**近 7 天（含日/周）免费**；**月报 / 年报 / 热力图 = `deepReport`（付费）**；免费侧**显示引导卡、不静默隐藏**。

| **月** | 🔒 周期按钮**置灰 + 内联「会员」标记**；点击不切换，显示**引导卡** | ✅ 完整月报 |

## 4. 门控接线设计（`deepReport`）

- **判定单点**：一律读门控矩阵 `featureAllowedFor(FeatureKey.deepReport, tier)`（阶段 4 单点，`entitlement_matrix.dart`），**禁止页内散写 `tier == premium` 三元**。
- **拦什么 / 拦在哪**（全部在报告段表现层，家长端可引导购买）：
  1. **月/年周期按钮**：免费档 → 按钮置灰 + 内联「会员」；`onTap` → **不放行切换**，弹引导（对齐 C62「不可点≠静默 null」）。
  2. **热力图区块**：免费档 → 渲染 `PremiumUpsellCard(feature: deepReport)`，其中「查看详情」→ `context.push('/parent/premium')`（家长端合法引导，与阶段 4 家长端方案一致）。
  3. **近 4 周稳定性卡**：按 DR1 结论决定是否门控。
- **免费档看到什么**：日/周报告**完整可用**（全部指标）；月/年/热力图位置**可见但锁定**，附「解锁完整报告」引导卡 → 购买页。

### 4.1 🔴 `deepReport` 中间态裁定（team-lead 2026-10-15 拍板）
