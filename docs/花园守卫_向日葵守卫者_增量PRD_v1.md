## 1. 背景与目标

### 1.1 现状（读码事实，不推测）

| 碎片是**玩家级单例行余额**（`premiumFragmentBalance` / `setPremiumFragmentBalance`），来源只有开花（瞬间 15% / 每日晨露 15%） | `bloom_reward_repository.dart`、`prd_params.dart` |

### 1.2 目标（3 个，正交）

- **G1 一个"不打扰专注"的每日悬念**：给今日页一个「昨晚发生了什么」的期待，把**打开 App 的理由**从"我要盯着"改成"我要收报"。**奖励与盯屏时长零相关**。
- **G2 让花园的"安全感"具象化**：花草会被东西惦记 → 有人在门口守着。把抽象的"养护"变成可讲述的故事，提升家长对"这游戏不是打怪"的认可。
- **G3 零通胀的收集长线**：用**图鉴**（不是货币）承载长线留存，把货币通胀风险关在门外。

### 1.3 User Stories

- 作为**孩子**，我晚上付 5☀ 让阿葵上岗，第二天早上打开就能看到「昨晚 3 只偷菜贼都被赶走了」，还想知道来了哪种。
- 作为**孩子**，我第一次赶走「灰尾浣熊」就解锁一张卡片，卡片背面有一句"浣熊洗食物其实是在摸食物"的小知识，我想集齐 6 张。
- 作为**孩子**，我某天忘记付钱，菜地只被踩乱了一点、什么都没丢（文案明确告诉我），我不会因此讨厌这个游戏。
- 作为**家长**，我看到这个玩法**只要付钱 + 看战报**，不需要孩子盯着屏幕打怪，我愿意为买断档付费。
- 作为**家长**，我不担心孩子为了刷奖励一直开着 App —— 因为奖励与在线时长无关。

## 2. 已定决策 与 我的异议

| 项 | 玄参已定 | 我是否同意 | 说明 |
|---|---|---|---|
| 玩法名 | 向日葵守卫者 | ✅ | — |
| 位置 | 孩子端「今日」页 | ✅ | 附带好处：今日页**不计入娱乐时长**（`kAppUsageCountingTabs = {2,3,4}`，今日=0）→ 玩法不会被防沉迷拦，也不会拖长"娱乐时长"。 |
| 形态 | 离线制，绝对不能实时 | ✅ **强烈同意**，并把它升级为**可验证的硬指标**（§3.4） | 见下方异议 1。 |
| 画面 | 左房子+花园+守卫者在门前；右侧偷菜贼从右往左 | ✅ | 落地为「120pt 迷你舞台卡 + sheet 大舞台」。 |
| 成本 | 每天 5 阳光 | ⚠️ **接受，但要盯住低龄账** | 见异议 2。 |
| 奖励 | 含碎片倾向，但"还要再想想" | ⚠️ **建议碎片降级为彩蛋** | 见异议 3。 |

**异议 1（必须写进验收）**：光说"不能实时"挡不住实现漂移。**加一条可测指标**：
> **奖励恒等式**：任意一天，`当日返还阳光 + 碎片` **只**是「是否付契约 × 离线时长」的函数，**不是**「App 前台时长 / 打开次数」的函数。
> 验收做法：同一账号同一自然日，模拟「打开 1 次（24h 后）」与「打开 12 次（每 2h 一次）」两种路径，**两次结算的总产出必须逐位相同**（容差 0）。做不到就是设计跑偏。

**异议 2（低龄预算真的紧）**：4 盆「2 水 1 肥」已占低龄 88☀ 的 **88.6%**。再加守卫净支出 3☀/天 → **81/88 = 92.0%**；若那天还是极端天气再买棚（10☀）→ 91/88 = **103%**，当天必然超支。
→ 这不是否决 5☀，而是**三条可选缓释**（不改变玩法结构）：
1. 契约价 5 → **3☀**（净 1☀/天，占比 1.14%）；**最省事**，但"5"这个数字玄参已点名。
2. 返还下限 1 → **2☀**（E[返还] 2.00 → 2.75，净 2.25☀/天，占比 2.56%）。
3. 接受 92%，靠 Lv.5 浇水折扣（5→4）继续消化 —— 现状本来就要求低龄走 2 水 1 肥。
**我的建议：先按 5☀ 上线，把①作为"低龄反馈不好就拧"的备用阀门**（改一个常量，零结构变更）。

**异议 3（碎片会通胀）**：现有碎片产出估算 **≈0.25 片/天**（4 盆普通、满养护，算式见 §5.3）。若守卫按"每天 2 只 × 1 片"发，日均 +2 片 = **8 倍**现有产出 → 10 片一株的普通植物、20 片一株的精英植物会被瞬间打穿，F144「6→10 / 10→20」那次提价等于白提。
→ 结论：**碎片只能当彩蛋**，且必须日/周双上限（§4.2 / §5.3）。

## 3. 玩法规则（可直接开发）

### 3.1 值守契约（唯一付费点）

| 项 | 规则 | 常量 |
|---|---|---|
| 价格 | **5 ☀**（一次扣费，写账本一行） | `kGuardContractPrice = 5` |
| 有效期 | **24 小时**（滚动窗口，从付款瞬间起算，**不按 0 点重置**） | `kGuardContractHours = 24` |
| 可否重复付 | **不能**。契约未到期时按钮变「守卫在岗 · 剩 18h」且不可点 | — |
| 到期后 | 需孩子**再次主动**付款，**绝不自动续费、绝不静默扣费** | — |
| 余额不足 | 按钮置灰 + 文案「还差 N ☀」，**不给任何垫付/欠费** | — |

**为什么用滚动 24h 而不是自然日**：① 避免「0 点一到钱被扣了孩子不知道」；② 避免跨天窗口被切成两截、收益对不上；③ 实现上"契约到期时间"可由账本直接推出（§6.1），**不需要新增任何存储**。

### 3.2 时间结构：巡逻槽（slot）

契约期内，以 **付款时刻为锚点**，每 **6 小时**切一个巡逻槽：

```
付款 20:00 ──┬── slot1 20:00–02:00 ──┬── slot2 02:00–08:00 ──┬── slot3 08:00–14:00 ──┬── slot4 14:00–20:00 ──┤ 契约到期
             └──────────────────────┴──────────────────────┴──────────────────────┴──────────────────────┘
```

| 项 | 值 | 常量 |
|---|---|---|
| 槽长 | 6 小时 | `kGuardPatrolSlotHours = 6` |
| 每契约槽数 | 4（24÷6） | `kGuardPatrolSlotsPerWindow = 4` |
| 每槽来贼概率 | **50%**（确定性哈希，seed = `dayKey + slotIndex + kGuardSaltV1`，**禁用 Random**） | `kGuardThiefChance = 0.50` |
| 每槽最多贼数 | **1**（不做"一群"，避免刷屏与数值放大） | — |
| 槽归属判定 | 取**槽中点**是否落在契约区间内（简单、可重放、无边界争议） | — |
| 有贼但不付钱 | 该槽记为「得手」，触发 §3.7 的封顶损失 | — |

**为什么 6 小时、50%**：
- 6h 保证「付完钱 6 小时内一定没有战况」→ 从物理上**不可能**出现"实时感"（孩子刚付完盯着看，什么都不会发生）。
- 4 × 50% = 期望 2 只/天，与"一天巡逻 4 次、偶尔撞见"的叙事一致；范围 0~4 只，够波动、够小不致失控。
- 用确定性哈希而非 Random：可重放、可测试、可调试、跨会话一致（与天气系统同款纪律）。

### 3.3 一只贼的一生（P0 无失败）

| 步骤 | 规则 | 数值 |
|---|---|---|
| 出现 | 槽结算时按哈希判定 | 50%/槽 |
| 贪心值（血条） | 每只贼 **2 格** | `kGuardThiefHp = 2` |
| 赶走 | 守卫每剑 −1 格，**2 剑**赶走；剑与剑间隔 1.2s（仅动画时长，不影响结果） | `kGuardSwingIntervalMs = 1200` |
| 胜负 | **P0 守卫 100% 胜**（不掷骰、无失败） | — |
| 每只产出 | **+1 ☀**（返还在同一个结算里一次性发，上限 3☀/天、下限 1☀/天） | `kGuardRefundPerThief = 1` / `kGuardRefundDailyCap = 3` / `kGuardRefundMin = 1` |

> **为什么 P0 不给"败北"**：① 儿童产品的失败反馈必须"可控可重来"，而离线制下孩子**无法干预**，任何失败都是"凭空的惩罚"；② 没有失败就没有"战力"需求，守卫者等级就不会变成必须刷的负担（见 §3.6）；③ 数值上，一旦引入败北，就必须同时引入"守卫等级 / 装备 / 补强"，成本翻倍且必然导致刷。

### 3.4 结算时机、幂等、离线窗口（实现关键）

**触发点**（都先跑一次 `settle`，幂等）：

| # | 触发 | 说明 |
|---|---|---|
| 1 | 今日页 `_reload`（首帧 / 切回 tab / 回前台 / 跨 08:00 或跨天） | 复用既有 `ChildTabAutoRefresh`（C68），**不新增定时器** |
| 2 | 花园页 `_reload`（P1） | 因为进度损失作用在植株上，花园可见时数据必须已经是结算后的 |
| 3 | 战报卡点击"刷新"（P2） | 手动兜底，防"停在页面上跨过槽边界" |

**`settle(now)` 纯流程**（给架构师）：

```
last = prefs.guard_settled_at              // 首次安装 = now（绝不补历史）
if (now <= last) { prefs.guard_settled_at = now; return; }   // 时钟回拨：不产事件
from  = max(last, now - 24h)               // 🔴 离线窗口封顶 24h
slots = 覆盖 [from, now) 的、且已完整结束的槽（按契约锚点切）
for slot in slots:
    guarded = 槽中点 ∈ [guard_from, guard_until)      // guard_until 由账本推出（§6.1）
    hit     = hash(dayKey + slotIndex + salt) % 2 == 0 // 50%
    if (!hit) → 记「平安」事件
    if (hit && guarded)  → 记「赶走」事件（+1☀ 计入 refund 累计）
    if (hit && !guarded) → 记「得手」事件（计入 progressPenalty 累计）
apply(progressPenalty  → 按 §3.7 封顶后写回 plant.progress，走 PlantRepository.savePlant)
apply(refund           → 一行账本 earn，refType='guard_refund'，净额 clamp(只数,1,3))
apply(图鉴首次        → TrackingRepository.track('guard_defeat', payload={kind}))
apply(碎片彩蛋        → 仅当 4 只全赶：setPremiumFragmentBalance(bal+1)，周上限 2)
prefs.guard_settled_at = now
prefs.guard_report_unread = 有事件 ? true : 保持
```

| 纪律 | 值 / 说明 |
|---|---|
| 离线窗口封顶 | **24h**（`kGuardSettleWindowMaxHours`）→ 离线一周回来**也最多按 1 天算**，不会攒 28 只贼、不会叠罚 |
| 首次安装 | `guard_settled_at = now`，**不补历史**（否则新装用户一进来就被罚） |
| 时钟回拨 | `now <= last` → 只把 `last` 前移，**不产事件、不发奖** |
| 幂等 | 唯一真源 = `guard_settled_at`；重复调用窗口为空 → 自然幂等 |
| 空花园 | 没有存活植株 → **无损失**（也不发返还，避免"空园刷钱"） |
| 新种下当天 | 该株**不参与**本次进度惩罚（与 C100-1「新种当天免疫」同款口径） |

### 3.5 离线战报怎么呈现

**原则：战报是"交班报告"，不是"战报邮件"。**

| 层 | 内容 | 触发 |
|---|---|---|
| **卡面（今日页，常驻）** | 一行摘要：`昨晚赶走 2 只偷菜贼 · +2☀` / `守卫在岗 · 剩 18h` / `今晚没人守门` | 恒显示 |
| **展开 sheet（大舞台 240pt）** | 左：房子+花园+阿葵在门口；右：本窗口的贼（最多 4 只，从右往左排队）；下方 **时间轴 0~4 行**（`21:40 · 🦝灰尾浣熊 → 阿葵赶走了 +1☀`） | 点卡面 |
| **一次 3 秒演出（P1）** | 时间轴底部一个按钮「看看阿葵怎么赶走的」→ 播**最后一次**赶走的序列帧（举剑 → 2 格血条清空 → 贼逃走）。**只在孩子主动点时才播，播完就停** | 点击 |
| **未读红点** | 有新战报时卡面右上角小红点，进 sheet 即消 | — |
| **不做"自由回放"** | 不做逐帧回放、不做录像、不做可反复播放的战斗 | — |

**为什么不做回放**：回放需要"逐事件存动画参数 + 全部序列帧"，成本 ≈ 整个 P1；而它的情绪价值在**第一遍**就吃完了。给"一次性 3 秒"最划算。

**战报最小间隔**：卡面战报**只在距上次战报 ≥ 4h** 且有新事件时刷新（`kGuardReportMinIntervalHours = 4`）—— 防"切 tab 就弹"。但**结算永远照常**（数据不延后），只是 UI 不刷。

### 3.6 守卫者的状态：要不要等级/熟练度

**结论：不要数值等级，只做纯装饰的"徽章 + 星级"。**

| 项 | 设计 | 数值影响 |
|---|---|---|
| 守卫者徽章 | 累计赶走 **10 / 30 / 60** 只 → 铜 / 银 / 金三档徽章**外观**（`kGuardBadgeThresholds = [10,30,60]`） | **零** |
| 图鉴卡星级 | 每种小怪物被赶走 **1 / 3 / 6** 次 → 1 / 2 / 3 星，3 星换一句新科普 + 金边 | **零** |
| 台词/小动作 | 徽章升级后阿葵多 1~2 句台词、多 1 个待机小动作 | **零** |

**"不会变成必须刷的负担"的论证**（三条，缺一不可）：
1. **没有失败判定** → 战力无处可用。若做"更强"，唯一能加速的是"2 剑 → 1 剑"，而奖励由**赶走只数**决定、跟剑数无关 → 等级对产出**恒为 0**。
2. **贼数由时间决定、与等级无关**（4 槽硬上限）→ 升级不能"多打几只"，因此没有"为了多打而升级"的路径。
3. **无衰减、无门槛、无赛季** → 不加也不会失去什么，加了只多一句话。**刷不出经济价值的东西，孩子不会刷**（而如果孩子愿意为了一句话去刷，那说明这玩法本身成功了）。

### 3.7 没付 5☀ 时：两个方向，给判断

| | **方向 A：会被偷（有损失）** | **方向 B：什么都没发生（零损失）** |
|---|---|---|
| 孩子的体感 | 「我忘了付钱，菜被踩了」 | 「我忘了付钱，昨晚什么都没发生」 |
| 付费动机 | 强（怕损失 + 想拿奖励，双驱动） | 弱（只有奖励驱动，5☀ 换奖励的性价比要自己算） |
| 挫败风险 | 中（取决于封顶）；**重罚必弃游** | 0 |
| 家长观感 | "有代价才有责任感"（多数家长接受**轻量**代价） | "不打怪也不亏"（更安全，但会问"那付钱干嘛"） |
| 实现成本 | 低（就是 §3.7 的封顶惩罚） | **更低**（一段文案） |
| 审核风险 | 无（无赌博、无内购、无恐惧元素） | 无 |
| 后续扩展 | 有（惩罚可分级、可被"增益道具"抵消） | 几乎无（玩法上限被锁死） |

**我的建议：走 A 的"轻量版"**，理由三条：
1. **5☀ 必须有对手才有意义**。零损失时，"守卫"这个叙事就塌了 —— 它退化成"付 5☀ 抽一个小奖"，与"守卫者"三个字完全不匹配，而这正是本玩法的全部情绪价值。
2. **重罚才可怕，轻罚不可怕**。全园 **≤2pp/天**（= 1/5 个自然成长日 ≈ 10☀ 的浇水价值）**在数学上不可能导致枯萎、死亡、花谢**（§3.8 五条保底），孩子丢的只是"一点点进度条"，甚至看不清。
3. **它让 5☀ 变成一个正期望的决定**：付 5☀ 避免约 10☀ 的进度损失 + 拿回 2☀ + 图鉴进度。孩子会自己算出来"该付"。

**但必须留一个退路**：`kGuardTheftProgressPenalty` 一旦设为 **0**，玩法立刻退化为方向 B，**其余代码零改动**。留给玄参一个常量的余地。

### 3.8 失败惩罚的边界：五条保底（**任何一条不得删**）

| # | 保底 | 值 / 规则 |
|---|---|---|
| 1 | **不做残缺式封顶之外的事** | 只扣 `plant.progress`（当前阶段 0~1 的浮点）。**绝不**扣阳光余额、碎片、种子券、晨露待收、花期、`bloomedAt`、`bloomCount`、枯萎计时、`wiltedAt` |
| 2 | 每只 −0.5pp，**全园单日封顶 −2.0pp** | `kGuardTheftProgressPenalty = 0.005` / `kGuardTheftDailyCap = 0.02` |
| 3 | **不动小进度** | 当前阶段 `progress < 0.01` 的植株**完全免疫**（保护刚种下/刚花谢回落 0.5 附近的边界情况） |
| 4 | **按比例再加一道闸** | 扣完不得低于 `progress × 0.90`（最多扣掉剩余进度的 10%）→ 进度越满越安全 |
| 5 | **窗口封顶 + 穷孩子免罚** | 离线窗口 ≤24h（保底 4 → 最多罚 1 天）；**阳光余额 < 10☀ 当天自动免费上岗**（`kGuardFreeRideBalance = 10`，不扣费、不发奖、不处罚） |

**最坏情形核算**（4 盆、30 天成株、完全不付钱）：
`每天 −0.5pp/株` → 单株日成长 10pp → 9.5pp → **成株从 30 天变 31.6 天（+5.3%）**。不会死、不会枯、不会花谢。

**"一觉醒来损失惨重"在数学上不成立**，因为：① 单日封顶 2pp；② 离线封顶 24h；③ 保底 3/4 双重免疫；④ 穷孩子免罚。**这四条同时成立，最坏单次打开看到的损失是 4 盆 × 0.5pp。**

| 差距项 | 打怪的孩子 | 不打怪的孩子 | 差距的实际重量 |
|---|---|---|---|
| 阳光 | 净 −3☀/天 | 0 | 打怪的**反而少 3☀/天**（这是设计意图：它是 sink） |
| 碎片 | +0.42 片/周 | 0 | 10 片 = 1 株普通植物 → 差距 = **每 24 周多 1 株普通植物**；而阳光通道 300☀ ≈ **3.4 天收入**就能种 → **碎片不是瓶颈，差距无感** |
| 进度 | 无损 | 最坏 −2pp/天（成株 +5.3%） | 唯一真实的差距；被五条保底锁死，且穷孩子（<10☀）免罚 |

**结论**：
1. **货币层面：不打怪不吃亏**（守卫是净支出，不是收入）。
2. **图鉴/种子券：不打怪少一份"乐趣与一次性礼物"**，但不影响"能否种出所有植物"（阳光通道始终在，且阳光是主通道）。
3. **唯一需要盯的是进度损失**（−2pp/天）→ 用五条保底 + 穷孩子免罚兜住；**若日后数据发现"不付钱的孩子流失高"，第一个动作就是把 `kGuardTheftProgressPenalty` 调成 0**（退化为方向 B，零结构变更）。

## 5. 经济测算（算式全部写出）

### 5.1 5☀ 占日收入多少

| 年龄档 | 真实日收入（§7 基线） | 5☀ 占比 | 净支出 3.00☀ 占比 |
|---|---|---|---|
| 低龄（6–8） | 88.0 ~ 100.0 ☀ | 5.68% ~ 5.00% | **3.41% ~ 3.00%** |
| 中龄（9–10） | 118.0 ~ 130.0 ☀ | 4.24% ~ 3.85% | 2.54% ~ 2.31% |
| 高龄（11–12） | 148.0 ~ 160.0 ☀ | 3.38% ~ 3.13% | 2.03% ~ 1.88% |

**期望返还算式**（4 槽、p=0.5、返还 = `clamp(只数, 1, 3)`）：

```
P(k) = C(4,k) · 0.5^4  →  k=0..4 = [0.0625, 0.25, 0.375, 0.25, 0.0625]
返还(k) = [1, 1, 2, 3, 3]
E[返还] = 1×0.0625 + 1×0.25 + 2×0.375 + 3×0.25 + 3×0.0625
        = 0.0625 + 0.25 + 0.75 + 0.75 + 0.1875 = 2.0000 ☀/天
净支出 = 5 − 2.00 = 3.00 ☀/天
```

### 5.3 通胀测算与上限

**现有碎片产出（估算，算式写明）**：
```
单盆每轮复开花周期碎片期望（普通档）：
  开花瞬间 15% × 1 片 = 0.15
  花期内每日晨露 3 天 × 15% × 1 片 = 0.45
  合计 0.60 片 / 周期
周期 = 7 天（满养护）~ 14 天（零养护）
→ 0.086 ~ 0.043 片/盆/天；4 盆 = 0.17 ~ 0.34 片/天，取中值 ≈ 0.25 片/天
```

| 产出项 | 期望/天 | 期望/月 | 相对现有 7.5 片/月 | 上限（硬） |
|---|---|---|---|---|
| 碎片（4 只全赶） | 0.0625 片（P(4)=6.25%） | **+1.9 片** | **+25%** | **2 片/周**（≈8.7 片/月，几乎不触发，只作护栏） |
| 阳光返还 | 2.00 ☀ | +60 ☀ | — | 3 ☀/天 |
| 净阳光 | **−3.00 ☀** | **−90 ☀** | — | — |
| 种子券 | 一次性 | 1 张普通档（=10 片 / 300☀ 等价） | 终身一次 | 集齐 3 张只发 1 次 |

**通胀结论**：
- 阳光：**负向**（每月净 −90☀ ≈ 0.3 株普通植物 / 0.56 次低龄扩容），不构成通胀。
- 碎片：**+25%/月**，在"F144 已把普通 6→10、精英 10→20"的余量内；一旦 `kGuardFragmentWeeklyCap` 被放开到 ≥3，通胀立刻破防 —— **这个常量是本玩法唯一的经济红线**。
- 种子券：**一次性 300☀ 等值**，与 C74 已接受的一次性注入（102☀）不同量级，但它是"集齐 3 张"的长期目标（约 2~4 周），且要求每天付 5☀（≈ 累计已付 100~150☀）→ **实际净赠予约 150☀ 等值**，可接受。**精英券暂不给（→ 付费档 / P2）**。

| 形象 | 草 🌿 / 蝗虫 🦗 | 哺乳类（§8） |

**风险与缓解**：孩子看到"今日页有贼"→ 跑去花园找 → 找不到。

### 6.4 物种图鉴（守卫者**不是新物种**）

### 6.5 付费边界（买断档）

| 档位 | 能玩吗 | 给什么 |
|---|---|---|

| **买断档** | 加「体验与长线」 | ① 图鉴 **6 → 12 种**（多 6 种小怪物 + 科普）；② 集齐 12 张 → **精英档种子券 ×1**；③ 守卫者**皮肤 ×1**；④ 战报"3 秒演出"**可重看**（免费档只能看一次） |

**高度预算（必须是数字，不是"看起来还行"）**

> 口径依据：今日 tab 是沉浸式的（`child_shell_page.dart`：`extendBodyBehindAppBar: _index==0`）→ **body 高 ≈ 屏高 − 底部导航 80pt**，body 顶从 y=0 起算，故 `sceneGap = 0.40 × 屏高` 相对于 body 顶成立。以下均按此口径算。

| 设备 | body 高（含 nav 80pt） | 场景区 = 0.40H | 按钮区 | ListView 可用 | 现有内容 | 余量 | 加守卫卡 120+10 后 |

| iPhone SE 375×667 | 587 | 266.8 | 78 | 242.2 | 244 | −1.8 | 需滚 126pt |
| iPad 11″ 834×1210 | 1130 | 0.40×1210 + 下移 100 ≈ 584 | 78 | 468 | 244 | 224 | **不需要滚动** ✅ |

**结论与取舍**：
- iPhone 上「今日必做」卡会被推下 ~26pt（滚一下就到）；SE 上需要滚一次。**这个代价换"今日页就能看到花园与贼"，我建议接受** —— 但必须配一个兜底：

## 11. 分期建议（完整版 ≈ 2 周；MVP ≈ 4.5 人日）

### P0 · 最小可玩（≈ 4.5 人日，**必须一次做完才算能上**）

| # | 内容 | 说明 |
|---|---|---|
| 1 | 值守契约 | 5☀ 扣费（走 `append` + `guard_pay`）、24h 到期、在岗不可重复付、余额不足置灰 |
| 2 | 离线结算纯函数 | `settle(from,to,guardWindow)`：4 槽 × 50% × 赶走/得手；**纯函数 + 可单测 + 可重放** |

| 4 | 返还与惩罚 | 账本 `guard_refund`（clamp 1~3）；进度惩罚**五条保底**全实现 |
| 5 | 今日页守卫卡（120pt，静态） | 舞台用 **emoji**（🏠🌱🌻🦝）先顶，**先不做正式立绘**；文字行 + 按钮；小屏折叠 |

| 8 | 文案 | 全部进 ARB（zh/en），`refLabelOf` 补 2 条 |

**P0 验收（可执行）**
- 幂等：同一 `now` 连调 10 次 `settle`，账本/进度/图鉴变化 = **1 次**的量。
- 奖励恒等式：`1 次 24h 后打开` vs `12 次每 2h 打开` → 总返还与总赶走数**逐位相同**。
- 封顶：构造"离线 7 天"→ 只结算 24h；构造"4 只全得手"→ 进度只掉 2pp。
- 穷孩子：余额 4☀ → 不扣费、不处罚、不发奖。
- 时钟回拨：`now < last` → 零事件。

### P1 · 收集与情绪（≈ 4 人日）

图鉴 6 种（`guard_defeat` + 卡片 sheet + 首次解锁提示）｜集齐 3 张 → 普通种子券 ×1｜集齐 6 张 → 金徽章 + 2 片碎片｜「3 秒挥剑演出」一次性｜守卫者徽章 10/30/60｜碎片彩蛋（4 只全赶 → 1 片，周上限 2）｜花园页 `_reload` 也挂 settle。

### P2 · 长线与付费（≈ 5 人日，需 P0/P1 数据支持）

图鉴 6→12（付费档）｜精英种子券（付费档）｜守卫者皮肤｜星级 1/3/6｜天气文案联动（大风/暴雨）｜「今晚安睡」增益（**若坚持要做**）｜花园门口脚印装饰。

### 明确砍掉的（不排期）

| 砍掉 | 理由 |
|---|---|
| 实时刷怪 / 需盯屏的战斗 | 违反唯一硬约束（玄参已否决） |
| 守卫者战力/装备/等级 | 无失败判定 → 数值无意义 → 只会变成刷（§3.6 三条论证） |
| 逐帧自由回放 | 成本 ≈ P1，情绪第一遍就吃完 |
| 花园摆件系统（R4） | 新实体 + 排布 UI + 美术，成本最高、收益最低 |
| 贼出现在花园页 | 会与杂草/害虫混淆（§6.3） |

## 12. 调试与验收口径（新玩法必须可调）

复用 `bloom_debug_panel.dart` 的纪律：**入口与面板由 `if (kDebugMode)` 守卫；面板只调领域服务，不直写库；release 构建零残留。**

| 调试按钮 | 行为 |
|---|---|
| 「拨回 6 小时」 | 把 `guard_settled_at` 前移 6h（模拟离线了一个槽） |
| 「立即结算」 | 直接跑 `settle(now)` |
| 「强制来 1 只贼」 | 覆写下一个槽的哈希结果（不写业务库，只写 debug override provider） |
| 「随机 0~4 只」 | 覆写整窗口结果 |
| 「契约剩余时间 ±6h」 | 改 prefs 的 `guard_settled_at` / 走一次假 `guard_pay` 账本 |

**埋点（复用 `TrackingType.metric`）**：`guard_contract`（付款，payload: price/余额）、`guard_settle`（payload: slots/hit/defeated/stolen/refund）、`guard_defeat`（payload: kind）、`guard_report_open`（战报打开率）。**用于验证 Q1（罚不罚）与 Q3（碎片是否通胀），这两条必须上线 2 周后回看。**
