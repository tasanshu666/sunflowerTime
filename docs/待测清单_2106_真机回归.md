## 0. 🔴 P0-1 权益态购买后即时刷新（一键 FAB / 扩容格）

> 这是 2105 带出去的唯一缺陷，**2106 的核心修复点**。写在第一条，因为它是唯一一条
> 「用户刚付完钱就会撞上」的问题。

### 缺陷是什么

`garden_page._entTier` 是用来判断「当前用户是不是买断会员」的那张身份卡，花园里有两处门控依赖它：

| 门控 | 免费档 | 买断档 |
|---|---|---|
| 一键照料悬浮 FAB | **不显示** | 存活株 ≥3 时显示 |
| 花盆扩容格 | 容量上限 **4**，不给扩容格 | 上限 **12** |

旧代码（`49c6500` 第 1799 行，即 2105 的写法）：

```dart
EntitlementTier get _entTier => ref.read(entitlementProvider).tier;  // ❌ 只读一次，不订阅
```

`ref.read` = **当前这一刻读一次**，之后对方变了也不通知。旧注释的前提是「购买发生在家长端，回到花园会重新读」，
但这个前提在 `IndexedStack` 保活下**不成立**：孩子端 5 个 tab 切换只换 index，页面不重建、`build` 不重跑
⇒ 花园页从挂载那一刻起再没问过这张身份卡。

**用户看到的**：家长付款成功 → 切回孩子端花园 → 还是一副免费样子（FAB 不出现、扩容格不出现）
→ **杀掉 App 重开才正常**。

**性质澄清（写进清单是为了避免下次重新排查）**：

- **不是资损**。领域层 `MatrixEntitlementService` 是另一套独立服务，判定本来就是对的；
  权益数据、扣费、账本全部正常，只是**界面没刷新**。
- **纯免费用户 0 影响**（旧值 free / 新值 free，结论相同）。
- **只影响付费用户，且恰好是付款完成那一刻** —— 内购类 App 最招差评的位置。

### 2106 的修法

```dart
EntitlementTier get _entTier => ref.watch(entitlementProvider).tier;  // ✅ 订阅，变化即重建
```

- 代码位置：`lib/presentation/child/pages/garden_page.dart:2018`（已改，当前 HEAD 已是 watch）
- 单元守卫：`test/m3/garden_fab_entitlement_reactive_test.dart`（3 例：免费不显示 / 买断出现 / 状态变化即时重建）
