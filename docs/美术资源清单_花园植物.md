## 1. 命名契约（文件名即接口）

**五级回退**，从最精确往回找，全部找不到才用内置自绘占位（`plant_artwork.dart` 的 `PlantArtCandidates.forPlant`）：

```
① assets/plants/{speciesId}_{stage}_{status}.png   ← 最精确（特殊态用）
② assets/plants/{speciesId}_{stage}.png            ← 该阶段通用（基础态用）
③ assets/plants/{speciesId}.png                    ← 该物种通用（不分阶段）
④ assets/plants/shared_{stage}_{status}.png        ← 新增：跨物种「通用」该阶段·该状态
⑤ assets/plants/shared_{stage}.png                 ← 新增：跨物种「通用」该阶段
⑥ 都没有 → 内置自绘简笔（PlantPlaceholderArt）
```

> ⚠️ **物种级恒优先于通用级**（① ② ③ 先于 ④ ⑤）→ 仅在**幼苗 / 成株 / 开花**阶段有意义。**种子阶段一律走通用级**（`shared_seed*.png`），**禁止任何 `species_*_seed*.png`**（见宪法 C20）；代码 5 级回退已保证：种子期任意物种都落到 `shared_seed*` 三张通用图。

**玄参本轮实际采用的命名模式（合法、推荐沿用）**：

```
基础态（成长中）      species_sunflower_seed.png / _sprout.png / _adult.png      ← 用二级
特殊态（萎/死/盛开）  species_sunflower_adult_wilting.png / _dead.png / _bloomed.png ← 用一级
```

- **只支持 PNG**（候选文件名在代码里硬编码为 `.png`）
- 目录已注册：`pubspec.yaml`（`- assets/plants/`）；`assets/pots/`、`assets/garden/` 本轮新增
- 解析结果按「物种_阶段_状态」**进程内缓存一次**，改图需重装/重启
- 坏图不崩：解码失败自动回退占位

**变量取值**（必须是这几个字符串，大小写敏感）：

| 变量 | 取值 | 出处 |
|---|---|---|
| `{speciesId}` | `species_sunflower` / `species_daisy` / `species_cactus` | `lib/data/local/plant_seed.dart:20-48` |

## 3. 阶段 × 状态：可达性矩阵（**已按枯萎 3 天重新推导**）

**3 阶段**：`seed` 种子 → `sprout` 幼苗 → `adult` 成株
**4 状态**：`growing` 成长中 → `bloomed` 已开花 → `wilting` 枯萎中 → `dead` 已死亡

### 3.1 可达矩阵

| 阶段 | growing | bloomed | wilting | dead |
|---|---|---|---|---|
| **seed** 种子 | ✅ | ❌ 不可达 | ✅ | ⚠️ **普通不可达 / 精品可达**（见 §3.2） |
| **sprout** 幼苗 | ✅ | ❌ 不可达 | ✅ | ✅ |
| **adult** 成株 | ✅ | ✅ | ✅ | ✅ |

| 物种类型 | 可达槽位 | 合计 |
|---|---|---|
| 普通（向日葵、小雏菊） | 9 / 物种 | 18 |
| 精品（仙人掌） | **10 / 物种**（含 `seed_dead`） | 10 |
| **总计** | | **28 张** |

### 3.2 `seed_dead` 可达性推导（**本轮根据枯萎 3 天重新算过**）

**关键机制**：**枯萎期间植物仍在继续长大**。tick 顺序是 `_advanceGrowth`（推进阶段）→ `_applyBloomCycle` → `_applyWiltAndDeath`（判枯萎/死亡）（`plant_growth_service.dart:248-250`），而 `_advanceGrowth` **只对 `dead` 短路、不拦 `wilting`**。

- 枯萎触发：`now - lastWaterAt ≥ 3 天` → `wilting`（`:376-382`）
- 死亡触发：`now - wiltedAt ≥ 7 天` → `dead`（`:384-390`）

**① 普通植物（240h/阶段，自动成长 10%/天）—— 不可达**

| 天 | 发生了什么 | 结果 |
|---|---|---|
| 0 | 种下 | `seed` / `growing`，进度 0 |
| **3** | 距上次浇水满 3 天 | `wilting`，进度 30%，**stage 仍 seed** |
| **10** | ① 进度 = 10 天 × 10% = **100%** → 推进 `sprout`；② 同时枯萎已满 7 天 → 死亡 | 同一 tick 内**先推进、后判死** → `dead`，但 **stage 已是 `sprout`** |

→ 死亡时刻（第 10 天）**不早于**种子→幼苗的推进时刻，所以**普通植物永远见不到 `seed_dead`**。（临界同日，实现顺序决定它落在 `sprout`。）

**② 精品植物 · 仙人掌（480h/阶段，自动成长 5%/天）—— ✅ 可达**

| 天 | 发生了什么 | 结果 |
|---|---|---|
| 0 | 种下 | `seed` / `growing` |
| **3** | 距上次浇水满 3 天 | `wilting`，进度 **15%**，stage 仍 seed |
| **10** | 枯萎满 7 天 → 死亡。此时进度才 **50%**，**离 100% 还差一半** | `dead`，**stage 仍是 `seed`** ← **这就是 `seed_dead`** |

→ 因为仙人掌一个阶段要 20 天（普通只要 10 天），**死亡来得比阶段推进早**，所以**「种子阶段的死亡」在仙人掌上真实可达**。

> **结论**：
> - `species_sunflower_seed_dead` / `species_daisy_seed_dead` → **不要出**（出了也看不到）
> - `species_cactus_seed_dead` → **要出**（否则仙人掌会有 1 个状态落到自绘占位，与其它图风格不一致）
> - 玄参已出的 `species_sunflower_seed_dead.png` **留着无害**（只是不可达，不影响任何流程）

### 3.3 另一个不可达：`bloomed` 只在 `adult`

开花的唯一赋值点是 `stage == adult && 进度 >= 1.0`（`plant_growth_service.dart` 的 `_advanceGrowth`）。种子/幼苗阶段永远不会是开花态。

### 3.4 顺带说明「美术空白」是否还需要补

v1 清单提过 3 处占位重复（`seed_wilting` 同 `seed_growing`、`adult_growing` 同 `adult_bloomed`、仙人掌 `adult` 萎/死合并）—— **这些是「内置自绘占位」的问题，只要美术图到位就自动消失**。向日葵本轮已用正式图覆盖，**雏菊与仙人掌仍需出图**才能补上。

## 5. 图片规格要求（**已全部更新，出图前必读**）

> ⚠️ v1 的「512×512 / 正方形 / 圆形裁切 / 内切圆 86%」**全部作废**。现行规格见宪法 **C13**。

| 项 | 要求 | 原因 |
|---|---|---|
| 格式 | **PNG**（带透明通道） | 候选名硬编码 `.png` |
| **画布** | **1200 × 2000**（宽 : 高 = 3 : 5，竖版） | 植物 + 自带花盆的整体构图；**统一画布才能保证所有盆等大、底边齐平** |
| **花盆宽度** | **800 px**（占画布宽 66.75%） | 三张图必须完全一致，否则盆会大小不一 |
| **花盆底部** | **贴合画布底边**（`y = 2000`） | 保证 9 个格子底部严格对齐 |
| **盆心水平位置** | **`x = 600`**（画布正中） | 同上 |
| 背景 | **全透明** | 无圆形裁切，四角不会被切 |
| 圆形裁切 | **已取消** | 代码已移除 `BoxShape.circle` 与圆形底色 |
| 主体缩放 | **不随进度变化**（`growthScale = 0`） | 所有盆必须恒定大小；进度反馈交给盆下细进度条 |
| 小尺寸可辨识 | 草地格子内实际显示约 **90–110 px** 宽 | 同一张图也会用在养护卡片里 |

### 出图时的构图要点

1. **主体（含盆）占满画布下半部分**，盆底贴底、盆心居中 → 上方留白给植物生长空间。
2. **不要在画布四周留大片透明留白** —— 这正是 v1 出图的**真凶**：原图 2048×2048 但内容只占 **35%×30%**，`BoxFit.contain` 按整张画布缩放 → 花盆只显示约 29px，**改任何尺寸参数都救不回来**。
3. 各状态的**盆位置必须完全一致**（同宽、同底、同心），只有植物部分变化 —— 否则切换状态时盆会跳动。

### 归一化脚本（**每批新图入库后必跑**）

```bash
python3 tools/normalize_plant_art.py
```

- 幂等：glob 扫描 `assets/plants/*.png` 与 `assets/pots/*.png`，**新增图自动纳入**
- 自动裁掉透明留白 → 按统一规则重排为 **1200×2000**（盆宽 800、盆底贴底、盆心 x=600）
- 原图备份到 `assets/_originals/`（**不在** `pubspec.yaml` 声明内，**不会打进包**）
- 脚本产出后建议逐张核对：内容底边 = 2000、口沿宽 ≈ 800、盆心 x ≈ 600

## 附：开花节奏（供美术把握「等待感」）

| 项 | 值 | 出处 |
|---|---|---|
| 自动成长 | 10%/天（普通）、5%/天（精品） | `kPlantAutoGrowthScale = 1.0` + 阶段时长 |
| 浇水 | +1% 进度 / 次，5 阳光，**每天最多 3 次**，间隔 ≥30 分钟 | `kPlantWaterProgressGain / Cost / MaxPerDay / IntervalMinutes` |
| 施肥 | +3% 进度 / 次，10 阳光，**每天最多 1 次** | `kPlantFertilizeProgressGain / Cost / MaxPerDay` |
| 每日满养护 | 10 + 3×1 + 3 = **16%/天** | 由上述常量推出 |
| 完全不管 | 普通 **30 天**到开花（但第 3 天就枯萎、第 10 天死亡）；精品 60 天 | `plant_seed.dart:8-12` |
| 每天满养护 | 普通 **约 19 天**、精品约 28 天 | — |
| 有效专注加成 | 当日达成 WFD（≥15 分钟且完成率 ≥90%）→ 当日成长 **×1.3** | `plant_growth_service.dart` |
| **枯萎 / 死亡** | 3 天未浇水 → 枯萎；枯萎后再 7 天 → 死亡（**死亡全损，不退还任何资源** —— 2026-09-27 起，见宪法 C15） | `kPlantWiltDays = 3` / `kPlantDeathDays = 7` |
| **花期循环** | 盛开保持 **3 天** → 花谢（进度回落至 **0.5**，体型保持成株）→ 养满再盛开 | `kBloomDurationDays = 3` / `kBloomWiltProgressFloor = 0.5` |

→ 美术含义：**孩子每天看到的进度变化只有 3%（浇水 3×1%）～16%**，所以同一个阶段的图片会停留很久，而**状态切换（枯萎/盛开/死亡）才是视觉上的大事件**。**每个状态的辨识度比精细度更重要** —— 孩子是「一天看一点」，不是「一眼逐个放大看」。
