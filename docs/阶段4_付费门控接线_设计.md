## 0. 结论速览（先给结论）

**10 个 `FeatureKey`：6 个功能真实存在、可接门控；4 个功能未实现、绝不可接门控。**

| 可接门控（6） | 未实现·不可接（4） |
|---|---|
| `oneClickCare`、`gardenPotCapacity`、`taskTemplateCount`、`rewardTemplateCount`、`deepReport`、`parentReport`（⚠️ 见待明确 D1） | `multiChildProfile`、`exportShare`、`memoirExport`、`familySharing` |

**不接的原因（4 项）**：
- `multiChildProfile`：全仓只有「单个孩子昵称」（SharedPreferences），**无孩子实体 / 无档案列表 / 无多档案 UI**（C69 已注明「多档案 = 阶段 2 实现」）。
- `exportShare`：只有数据层 `TrackingRepository.exportJsonl(...)`，**无任何导出/分享 UI**；`parent_delete_page` 的「导出成册」是 `V2 上线`占位按钮（只弹 SnackBar）。
- `memoirExport`：`memoir_service.dart` **仅埋点 / 周快照，无任何页面**（C74 已裁定撤下该权益）。
- `familySharing`：`account_service.dart` 的 `linkFamily()` **直接抛 `UnsupportedError('account disabled in Plan B')`**；C69 标注「未拍板」。

**另外发现 3 个必须先拍板/处理的结构性问题（见 §5）**：
- **P1（阻断级）**：`entitlementProvider` **从未在启动时加载** —— 已购用户冷启动会被当成 free，直到进过购买页。阶段 4 必须补 bootstrap。
- **P2（阻断级）**：种子数据**远超免费额度** —— 内置任务 **9 条** > 免费 5；内置奖励 **6 条** > 免费 5。新装免费用户一上来就超限，「只拦新增」会让其**永远无法新增**。
- **P3**：阶段 1/3 的 4 个**守卫测试**刻意断言「全放开 / 关键页不得出现权益标识符」，阶段 4 收紧后**必然变红**，须随本批改写（这是预期内的阶段迁移成本，非缺陷）。

## Part A：系统设计

### 1. 实现思路

**核心难点**：
1. 门控要**单点收口**（矩阵是唯一判定源），但额度型门控需要「当前数量」，而既有 `PremiumGate` 只有布尔语义（`freeEnabled`），拿不到计数。
2. **红线 C69**：额度超限**只拦新增、绝不删已存数据**——判定点必须落在「新增动作」入口，绝不能落在「列表/settings 的规范化」上（否则旧数据被裁剪 = 事故）。
3. **红线 2**：未实现的功能绝不接门控（Apple 3.1.1/2.3.1 拒审风险）。
4. **孩子端 vs 家长端**提示形态必须分开：孩子端不得直接放「立即购买」（儿童 App + IAP 敏感），家长端才引导到购买页。

**框架/库**：无新增依赖。复用 Riverpod（`entitlementProvider`）、go_router（`/parent/premium`）、既有 `PremiumGate` 与门控矩阵。

**架构模式**：分层 + 依赖倒置（域层纯 Dart，平台/IO 在 data/platform）。

### 2. 拦截层选择（与既有 `PremiumGate` 的关系）

**结论：以「表现层薄壳」为主拦截层（承载全部 UX），并以「域层防线」加固花盆扩容这一条会改经济/容量的路径。**

| 层 | 职责 | 与 `PremiumGate` 的关系 |
|---|---|---|
| **表现层薄壳**（`PremiumGate` / 新增 `PremiumQuotaGate`） | 全部 **UX**：置灰 + 内联原因 + 1s 轻提示；家长端跳购买页 | **扩展现有组件**：`PremiumGate` 用于布尔能力（`oneClickCare`）；新增**配额型**静态入口 `PremiumQuotaGate.onTap`（吃「当前数量」）用于计数能力。二者共用矩阵单点。 |
| **域层防线**（仅 `PlantGrowthService.expandPot`） | 防绕过：把既有写死的 `>= kGardenPotCapacityMax` 泛化为**按档位上限** | 域层**不 import** Riverpod / `PremiumGate`；注入既有域服务 `EntitlementService`（`can`/`quotaOf` 本就是域层单点）。 |

**为什么计数型主要靠表现层**：任务/奖励模板的增删都在**家长端唯一入口按钮**（`_openEditor` / `_addTemplate`），`TaskRepository.saveTask` / `RewardRepository.saveTemplate` 是**编辑与新增共用的 upsert**，在仓储层无法区分「新增 vs 编辑」，硬拦会误伤编辑。故计数型门控落在「新增入口」，并**只拦 create、放行 edit/delete**（对齐 C62「只拦真正违规动作」）。

**为什么花盆要加域层防线**：`expandPot` 既改经济账本又改 `settings.gardenPotCapacity`，且 C70 明令「矩阵只管控资格、扣费仍走既有链路」——把资格上限下沉到域层，避免任何旁路一次性把资格顶到 12。

### 3. 免费额度怎么判（「只拦新增」的判定位 + 数据源）

新增纯函数（**唯一配额判定入口**，放 `entitlement_matrix.dart`，防判定孪生）：

```dart
/// 「新增」是否放行：整项被关 → false；不限额度 → true；否则 当前数 < 额度。
bool quotaAllowsAdd(FeatureKey f, EntitlementTier tier, int currentCount) {
  if (!featureAllowedFor(f, tier)) return false;
  final int q = featureQuotaFor(f, tier);
  return q == kUnlimitedQuota || currentCount < q;
}
```

| 能力点 | 判定位（函数/调用点） | 数据源（当前数量） | 只拦的动作 |
|---|---|---|---|
| `oneClickCare` | `garden_page._onOneClick` / `_showOneClickFab` | —— （布尔：`featureAllowedFor`） | 一键批量操作 |
| `gardenPotCapacity` | `garden_page._confirmAndExpand` + `ExpandPotSlot` 出现条件；`PlantGrowthService.expandPot`（域层防线） | `settings.gardenPotCapacity`（= 页面 `_capacity`） | 扩容（+1 盆） |
| `taskTemplateCount` | `parent_task_config_page._openEditor`（新增分支，`initial == null`） | `taskRepository.tasks().length` | 新增成长项 |
| `rewardTemplateCount` | `parent_reward_page._addTemplate` | `rewardRepository.templates().length` | 新增奖励 |
| `deepReport` | `parent_report_page` 的 `_StabilityCard` 区 | —— （布尔） | 4 周趋势/稳定性区 |
| `parentReport` | 报告页整体（⚠️ 建议保持免费，见 D1） | —— （布尔） | 报告页 |

**「只拦新增、绝不删」的落点纪律（硬约束）**：
1. 判定**只读**计数，**绝不**在门控路径调用任何 `delete*` / `clear` / `copyWith(gardenPotCapacity: lower)`。
2. 超限时**已存数据只读保留**：任务/奖励列表照常渲染全部条目；花盆照常可种/可养护全部已有盆位。
3. 超限语义：`currentCount >= quota` → 拦新增；待用户**手动删除**降到 `< quota` 后自然恢复（文案要写明这一点）。

### 4. UX 提示形态（对齐 C62）

**统一原则（C62）**：**不可点 ≠ `onTap:null`**；只拦「真正违规的动作」，其余放行到页面给**分因提示**；形态 = **卡片/按钮置灰 + 内联一行原因 + 1s 轻提示兜底**（对齐既有 `kOneClickHintHoldMs`+`kOneClickHintFadeMs`≈1.3s / `child_snack`）。

**家长端**（`parent_task_config_page` / `parent_reward_page` / `parent_report_page`）：
- 「新增成长项 / 新增奖励」按钮：超限 → **置灰**；按钮旁**内联**文案「免费版上限 N 条（当前 M 条，已超出，可删除多余条目后新增）」。
- 点击（若仍可点，走分因）→ **1s SnackBar** + 可含**一个「了解会员」按钮 → `context.push('/parent/premium')`**（家长端允许引导购买）。
- 报告页 4 周区：整体替换为一张**升级引导卡**（复用 `PremiumUpsellCard` 风格），内含「查看详情」→ `/parent/premium`；**7 天分布 / 顶部主卡 / 护眼统计照常展示**（免费边界「近 7 天报告」）。

**孩子端**（`garden_page` 一键操作 / 花盆扩容）：
- 🔴 **不放任何购买按钮 / 价格**（儿童场景，避免 3.1.1 关联风险 + 家长投诉）。
- 一键操作 FAB：free → **不出现**（它是「省事增强」，单株浇水/施肥/护理仍在，功能不退化；`kOneClickMinPlants` 阈值逻辑保留）。
- 花盆扩容「+」格：free 且 `capacity >= 4` → **不出现**（新装 free 容量=4，天然无「+」格）；若出现某 legacy 态需提示，走**分因轻提示**「在家长天地解锁更多花盆哦」。
- 所有孩子端提示走既有 `_showBatchHint`（居中 Overlay，1.3s）或 `child_snack`，**不出**付费弹窗。

### 5. 升级 / 降级时已存数据的行为（对齐红线 1）

- **升级（买断 / 恢复购买）**：`parent_premium_page._buy/_restore` 成功后刷新 `entitlementProvider` → `PremiumGate` 自动放行；**已存数据完全不动**（无需迁移）。原被隐藏的「+」格 /「新增」按钮即时恢复可用。
- **降级**：本产品**无订阅、无过期**（一次性永久买断），**不存在真实降级**。
- **唯一的「收紧」场景**（阶段 4 上线瞬间）：历史上 free 态可无限创建 → 收紧后出现 `currentCount > quota`。处理 = **只读保留 + 只拦新增**（§3 纪律），**绝不裁剪**。花盆：`settings.gardenPotCapacity` 维持原值（如 legacy=12 的 free 用户保留 12 盆，只是不能再扩容）。

## 与既有实现纪律的对齐

- **`prd_params.dart` 单点收口**：`kFreeTaskQuota` 等已在 `entitlement_matrix.dart` 登记并引用 `prd_params` 容量常量（`kFreeGardenPotQuota = kGardenPotCapacityDefault`）——**不新增裸字面量**。
