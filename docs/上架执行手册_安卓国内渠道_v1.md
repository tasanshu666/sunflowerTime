## 0. 四句话结论（先看这个）

1. **软著著作权人 ≠ 父亲的名字** —— 要填**营业执照上的名称**（如「深圳市××区××软件商行」），不是经营者姓名。填错主体 → 商店必驳回。
2. **「IPC 备案」实为两件事**：网站 ICP 备案（`sunfocused.cn` ✅ **已做**）与 **APP 备案（工信部）**。上架的硬卡点是 **APP 备案**。
3. **APP 备案不需要正式版安装包** —— 只要 App 图标 + 包名 + 公钥 + **证书 MD5 指纹**；安装包仅用于「备案智能助理」自动提取这些值，**可用任何已签名的 APK**（不必是正式发布版）。
4. **安卓付费：个体户开得了微信/支付宝收款，但商店不让在 App 里跳站外付** —— 支付通道能开（个体户是合法商户主体），卡点在**商店审核规则**：数字商品必须走平台 IAP，站外支付会被判违规。

## 3. APP 备案（工信部）—— 上架的真卡点

> 用户口中的「IPC 备案」= **网站 ICP 备案** + **APP 备案**。商店要的是后者。
> ✅ **好消息**：网站 ICP 备案已用阿里云服务器做完，`sunfocused.cn` 已备案 → 接入商与服务器前置**已满足**。

### 3.1 我们必须做 APP 备案的判定依据

- 政策原文：**单机、不联网**的 App，**不需要**上架分发平台时可不强制备案；**单机不联网但要上架应用商店 → 需要到云服务商（接入商）备案**。→ 我们要上架 ⇒ **必做**。
- 五大商店后台均有「ICP/APP 备案号」必填栏位，未填直接驳回。小米官方《应用资质FAQ》原文：**「所有应用上架均需要提供」**软著 + APP 备案，二选一软著形式（三选一）。

### 3.2 🔴 域名实名主体与备案主体必须一致（🔴 这是当前最紧急的技术活）

阿里云过户文档原文：**「如果您的域名已在中国内地完成ICP备案，若过户后域名持有者信息与备案中的主办者信息不一致，请尽快完成变更备案」**；且**「若不及时处理，可能导致网站被管局关停」**。

| 项 | 当前状态 | 必须变成 |
|---|---|---|
| 阿里云账号实名认证 | 待确认（大概率是个人） | **个体工商户**（营业执照 + 统一社会信用代码） |
| 域名持有者（`.cn` 实名） | 待确认 | **个体工商户名称全称** |
| ICP 备案主办者 | 已有备案（主体待确认） | **个体工商户名称全称** |

**三步走（顺序不能乱）**：

```
第 1 步：阿里云账号「个人认证 → 变为企业认证」（个体户按单位/企业口径提交营业执照）
         ↳ 官方说明：个人转企业**不受 30 天变更限制**；变更后**域名与 ICP 备案信息不会自动变更**，须手动做
第 2 步：域名控制台 →「域名持有者信息修改（过户）」，持有者类型改为「企业/组织」
         ↳ 提交营业执照扫描件 + 统一社会信用代码 + 联系人证件
         ↳ .cn 域名**任何持有者信息修改都要重新实名认证**，耗时 3~5 工作日
         ↳ 不影响 DNS 解析与网站访问；不触发重新备案（只要后续做变更备案）
第 3 步：ICP 代备案系统 →「变更备案」→ 主办者类型/名称改为个体工商户
         ↳ 若当前备案主体已是父亲个人 → 变更为单位，走「已备案网站如何更换主体」
         ↳ 若备案主体已经是该个体工商户 → **可能无需变更**，先查清楚再动
```

> ⚠️ **触发 60 天转出限制**：过户成功后 60 天内该域名禁止转出阿里云。近期无转出需求可忽略。
> 💡 **顺序建议**：先查清「当前域名持有者实名主体」和「当前 ICP 备案主办者」分别是什么 → 再决定是「变更备案」还是「过户 + 变更备案」。**别先过户再发现备案主体也要动**，两件事一起做最省事。

### 3.3 🔴 APP 备案需要什么素材？（回答「要不要正式版安装包」）

**公钥 + MD5 怎么拿（三条路，任选）**：

| 方式 | 怎么做 | 备注 |
|---|---|---|
| **A. 备案智能助理（最省事）** | 阿里云备案系统 → 备案智能助理 → **上传任意一个已用 release 密钥签名的 APK** → 自动提取包名/签名/公钥/MD5 | 🔴 **不必是正式发布版**，只要是 release 密钥签的 APK 即可（甚至 debug 包提取也行，但建议统一用 release） |

### 5.3 🔴 隐私政策必须按 Android 改写（否则必驳回）

现有文档 `docs/隐私政策_向日葵专注_v1.md` 写的是「仅 `ACCESS_NOTIFICATION_POLICY`，无网络权限」——**这只对 iOS 成立**。

Android 实际 merged manifest 会带入：

| 权限 | 来源 | 处置 |
|---|---|---|
| `INTERNET` | `billing:8.0.0` → `com.google.android.datatransport` | 隐私政策**必须如实披露**；若安卓版最终改走**平台 IAP**（非 Play Billing），此权限可随依赖替换而消除 |
| `com.android.vending.BILLING` | `billing:8.0.0` | 同上 |
| `ACCESS_NETWORK_STATE` | `just_audio` → media3 | 音频库附带，剥了可能伤播放，建议**保留并披露** |

> 💡 **免费版的一个红利**：若安卓版完全不接任何支付（连平台 IAP 都不接），`in_app_purchase` 在**安卓侧**可以退化为空实现 → INTERNET 与 BILLING 权限一并消失 → 隐私政策措辞几乎不用改，也彻底避开「国内商店不收 Play 结算」这条硬伤。
> ⚠️ **但不能直接删依赖**：`in_app_purchase` 是**全平台包**（iOS StoreKit + Android Play Billing），`lib/platform/iap_service.dart` 是**唯一** import 它的地方，iOS 侧 2105 已上线在跑。正确做法是**保留依赖 + 在平台层按平台分流**（`IapAdapter` 已是干净的适配缝，安卓侧换成空实现或平台 IAP 实现即可，**不动上层**）。

> 📌 **另有一条好消息**：`https://sunfocused.cn/privacy.html` 实测 **HTTP 200 ✅**，且域名**已备案** ✅、托管在**阿里云境内服务器** → 国内审核员访问稳定，不会再是「境外 EdgeOne Pages 访问慢」的问题。

## 6. 安卓付费（一次性买断）—— 主体能支付，但商店不让绕开

### 6.1 🔴 先分清三件被混为一谈的事

| # | 事项 | 个体工商户能否做 | 说明 |
|---|---|---|---|
| 1 | **开微信支付商户号** | ✅ **能** | 腾讯客服原文：主体类型选「**个体工商户**」，交 ① 营业执照 ② **经营者**身份证 ③ **对公银行账户 / 法人对私账户**（个体户常用本人卡）→ 账户验证走**法人微信扫码** → 审核 1–2 工作日 |
| 2 | **开支付宝商家账号** | ✅ **能** | 个体户可作经营主体，费率约 0.6% |
| 3 | **在 App 内用这些通道卖数字商品** | 🔴 **不能** | 商店审核规则禁止 |

> 📌 **所以「个体户能不能开通收费支付功能」这个问题的答案是：支付通道能开，App 内卖数字商品不能走这条路。** 卡点不在主体，在商店规则。

### 6.2 卡点：商店审核禁止绕开平台支付

已核到的官方/通则口径：

- **vivo 审核规范 3.1.6**（原文）：「应用开发运营及**收款**等相关主体应处于正常经营状态，不得借用、套用其他主体资质或以其他方式**规避相关责任**」
- **华为 IAP Kit 接入规范**（原文）：「**数字商品（虚拟商品）要求通过 IAP Kit 接入购买能力，不能独立对接支付宝、微信支付等三方支付**，否则可能影响应用上架」
- **商店审核通用高频驳回项**：「涉及虚拟商品、虚拟服务交易的 APP，**未使用平台指定的支付渠道，擅自接入第三方支付，或通过外部网页、二维码等方式绕开平台支付规则**，违规牟利」

**⇒ 你设想的「网站链接支付宝微信、App 内引导跳转」在商店审核里等于「绕开平台支付规则」，会被驳回。**

### 6.3 那 ICP 许可证到底要不要？

**要分清「谁在收钱」**：

| 场景 | 是否需 ICP 许可证 | 个体户行不行 |
|---|---|---|
| **走商店 IAP**（平台代收代付） | 通常不需（平台是持证经营方） | ✅ 可以 |
| **自建网站卖、App 只做站外引流** | 涉及经营性互联网信息服务 → 需 ICP 证（B25） | 🔴 **不行**（依法不予受理：须公司 + 注册资本≥100万 + 3人连续社保） |
| **App 内直接调微信/支付宝 API 收款** | 同上 | 🔴 同上，且商店审核也不允许 |

> 📌 **结论**：个体户 + 国内安卓 + 付费 = **只能走商店 IAP**。这条路合法，但有工程成本（见 6.4）。
> 📌 别被代办骗：市面上「个体户代办 ICP 许可证」**全部是虚假宣传**，材料提交到管局初审直接驳回。

### 6.4 走商店 IAP 的真实成本（选 C 路线时评估）

| 项 | 内容 |
|---|---|
| SDK 数量 | 华为 IAP Kit / 小米 IAP / OPPO / vivo / 应用宝 各一套 → **5 套** |
| 华为文档要求 | 服务端接收购买结果 → `jwsPurchaseOrder` **解码验签** → 发权益 → `finishPurchase` → **幂等补发货**（`PRODUCT_OWNED` / `SYSTEM_ERROR` 需补发） |
| 恢复购买 | `queryPurchases(productType=NONCONSUMABLE, queryType=CURRENT_ENTITLEMENT)` → 靠**商店账号**恢复，**不需要自建账号体系** ✅ |
| 一次性买断对应 | **非消耗型商品**（NONCONSUMABLE）= 永久拥有、不可重复购买 |
| 分成 | 华为 15%（游戏联运另议）；小米/OPPO/vivo/应用宝各有各自费率 |
| Flutter 生态 | 商店 IAP 多数**无官方 Flutter 插件** → 需写 MethodChannel 或自研插件 |
| 与项目红线 | 「不做账号、不做后端」——恢复购买靠商店账号可满足，但**服务端验签那套要建** ⚠️ |

### 6.5 建议决策（修正版）

> **首版安卓：只发免费版，买断留 iOS。**
> 理由：① 商店规则不允许站外支付，个体户无法用「网站收款」绕开；② 走商店 IAP 是 5 套 SDK + 一套服务端验签，属于独立工程；③ 免费版先把用户量做起来，等主体升级为**有限责任公司**（届时可办 ICP 证、付费类目也宽）再开付费。
>
> 💡 **不冲突的补充**：即便商店审核期不给付费功能，**官网 + 微信支付可以先跑起来做「种子用户」验证**——只要 App 内**不出现**跳转支付的引导，商店就不会因此驳回；把购买入口放在**官网**（sunfocused.cn 已备案 ✅）上，用户自行访问。

### 6.6 若将来要上安卓付费，路线顺序

```
主体升级为有限责任公司（拿到 ICP 证能力）
      ↓
先只接一家商店（建议华为：口径最松、文档最全）
      ↓
商品类型 = 非消耗型（NONCONSUMABLE）= 永久买断
      ↓
服务端验签 → 发权益 → finishPurchase → 幂等补发货
      ↓
恢复购买：queryPurchases(NONCONSUMABLE, CURRENT_ENTITLEMENT)
```
