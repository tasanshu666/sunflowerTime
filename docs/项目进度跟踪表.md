#### 1.10.8 🔴 两条实测「坑与教训」（可复用）

**① Dart `implements` 语义坑（本轮最大一次返工）**
给 `SunlightRepository` 加一个「带默认实现的抽象方法」`countByRefTypeAndRefId` 后，**`implements` 的实现类仍必须显式实现** —— Dart 的 `implements` **不继承默认实现**（只有 `extends` / `mixin` 才继承）。结果本仓 **45 个测试 fake 全部编译失败**，报 45 个 `Missing concrete implementation`。
**最终解法**：**不新增接口方法**，复用既有的 `countByRefTypeAndRefIdSince(..., DateTime.utc(1970))` 达到同效果。
✅ **本人已复核落盘事实**：接口 `lib/domain/repositories/sunlight_repository.dart:36/43` 现只有 `...OnDay` 与 `...Since` 两个方法（无新增）；`lib/domain/services/focus_level_service.dart:351/356` 正是走 `countByRefTypeAndRefIdSince(since = epoch)`。
⚠️ **纪律**：以后任何人想给接口加方法，**先数 `implements` 的实现类数量** —— `implements` ≠ 继承，加方法 = 全部实现类一起改。

**② 徽章宽度真实越界（守卫测试有效性的实证）**
`kLevelBadgeMaxWidth` 设 **230** 时，实测徽章右边界 **246.08 > 241.2**（阳光气泡区红线）→ 压到 **200** 才过。
✅ **本人已复核**：`lib/core/constants/prd_params.dart:1304` 现为 `const double kLevelBadgeMaxWidth = 200;`。
⚠️ 说明「口径守卫测试」不是摆设 —— 它真的抓到了一次越界。

**③ 🔴 C67 呼吸带在手机上从来不存在 —— 一个纯几何陷阱**

- **现象**：玄参在 **iOS 手机模拟器**发现今日页**第一张统计卡超出底图白色面板**（iPad 与小米 14 均正常）。
- **根因**：C67 的 36pt「呼吸带」= `0.40×屏高 − 0.37×屏高 = 3%×屏高`，🔴 **该等式只在分界线真的落在 `0.37×屏高` 时成立**，而那需要 `TabBackground` **主动对齐**；对齐计算被锁在 `isTabletOf(context)` 闸门（`tab_background.dart:84`）**仅平板生效**，手机端硬编码 `topCenter` ⇒ **手机上的分界线 = `0.8867 × 屏宽`**（`BoxFit.cover` 几何，**只跟屏宽有关**）。
- 🔑 **判据式**：**呼吸带 > 0 ⟺ 屏高 / 屏宽 > 2.2167**。
  - 所有 iPhone H/W ≈ **2.16~2.17**（SE 1.78）⇒ **每台 iPhone 呼吸带恒为负**（实测 390×844 缺 **8.2pt**、402×874 缺 **6.8pt**）；
  - iPad H/W = 1.45 虽远低于阈值，但**走对齐分支**故无恙；
  - **小米 14 H/W ≈ 2.59 在安全区 ⇒ Android 真机不会出现**。
  - ⇒ 这就解释了「**为什么玄参只在 iOS 模拟器看到，iPad 和小米都没事**」。
- **修法**：抽 `TabBackground.panelLineY()` 做分界线**单一真源**（与 build 同走 `geometryOf → tabBgAlignmentY → panelTopScreenY` 链），卡片起点改 `max(0.40×H, 实测分界线 + 3%×H)` —— **两个 C67 冻结常量原值未动、手机背景像素零变化（只动卡片不动背景）、iPad 逐像素不变**。
- 🔑 **留档价值（比修复本身更值钱）**：以后任何「某机型布局不对」的问题，**先算判据式再看代码**；同理，**任何跨平台的 ratio 型布局，都要确认该比例在另一 branch（平板 / 手机）下是否还成立** —— 「减法成立」的前提被闸门悄悄拿掉了，而减法本身看起来完全正常。
- ⚠️ **该缺陷自 C67 落地起即存在，非本轮新引入的回归**（避免后来者误以为是专注等级那个改动搞坏的）：已用 `child_today_page.dart` 本轮 diff = **100 插入 / 0 删除**（纯新增）+ 卡顶实测恒 `0.40×H`（与 C67 冻结值一致）**洗清**。

#### 1.11.4 🔴 坑：称号字号双重缩放（违反 C65）

- **现象**：iPad 上今日页徽章出现 **RenderFlex overflow 竖条**（黄黑条纹）。
- **根因**：称号字号**双重缩放** —— `× uiScaleOf` **叠加** `MediaQuery.textScaler`；iPad 1.3× 时「尚未解锁称号」6 字被撑到 ≈132pt，撑爆胶囊 `maxWidth`。
- **修法**：**去 `× s`**（文字只走 `textScaler`，图片才吃 `uiScaleOf`，**符合 C65**）+ 文案列包 **`Flexible`**（超量走 ellipsis 而非 overflow）。
- **留档价值**：C65「图片不吃 `textScaler` / 文字不乘 `uiScaleOf`」一旦两者**叠加就是双重缩放** —— 任何新增定尺寸文字元素都要按此自检。

### 1.17 本轮（2026-10-16 晚）：花园 · **C82 两 Bug 修复（盛开演出播两次 / 养护音效缺失）**（⚠️ **未提交**）

> 口径出处：裁定表 **C82**（玄参 2026-10-16 小米真机反馈）。**零 DB 变更、零迁移**（schemaVersion 不变）。真机验收 = **待玄参复测**。

| # | 修复 | 落点 | 结论 |
|---|---|---|---|
| ① | **盛开演出播两次** → 两处条件浮层加**稳定 Key** 防 remount | `garden_page.dart`（`_kCareEffectOverlayKey` / `_kGrowthFxOverlayKey`） | ✅ 挂载**恰好 1 次**（复现红灯 `Expected<1>/Actual<2>` → 绿） |
| ② | **四种养护动作无音效** → 同一动作**不发起成长 cue**、保留养护音效 | `garden_page.dart`（`_detectGrowthTransitions` 命中 → `playGrowthSfx: !sameActionCareSound`） | ✅ `care_water.mp3` 真实 `load`（复现红灯 → 绿） |
