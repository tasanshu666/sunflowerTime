# 签名密钥与发布

> 用途：钉死「向日葵专注」Android 发布签名的真源——密钥库在哪、密码在哪、换机器怎么恢复、出包怎么验签。
> 制定：寇豆码（Engineer）｜日期 2026-09-23｜状态：生效
> ⚠️ **纪律**：本文件及仓库内任何文档**都不得出现密码明文**。密码只存在 `android/key.properties`（不入库）与项目负责人的离线备份中。

---

## 1. 现状

Android release 构建**已改用自有发布密钥签名**。

- 此前（模板默认）：`android/app/build.gradle.kts` 的 `release` 沿用 `signingConfigs.getByName("debug")`，即 **debug 密钥**——属上架硬阻塞（应用商店拒绝 debug 签名包，且 debug 密钥随机器生成、无法作为长期身份）。
- 现在：`android/app/build.gradle.kts:40-49` 新增 `signingConfigs { create("release") {...} }`，`release` 块（`:52-62`，`buildTypes` 为 `:51-63`）改为读取该配置；签名参数从 `android/key.properties` 载入（`android/app/build.gradle.kts:10-17`）。
- 韧性：当 `android/key.properties` 缺失（CI / 新克隆未提供密码）时，`hasReleaseSigning=false`，release **回落 debug 签名**并打印告警，保证 `flutter run --release` 仍可本地调试；但此时产物**不可上架**。

## 3. 密码存放位置

- **唯一落地处**：`android/key.properties`（已被 `android/.gitignore:11` 忽略，**绝不入库**）。
- **离线备份**：由项目负责人保存在离线位置（钥匙串 / 邮件）。
- `android/key.properties` 的 `storeFile` 使用**相对路径** `upload-keystore.jks`（Gradle `file()` 相对 `android/app/` 模块目录解析），保证换机器、换绝对路径都能用。

> 缺失密码 = 无法恢复密钥库 = 无法再给本 App 出更新包。密码与 `.jks` 必须**分开保管**。

## 4. 换机器恢复步骤 / 出包 / 验签

### 4.1 换机器恢复（新克隆）

```bash
# 1) clone 拿到 .jks（有意入库）+ build.gradle.kts 的签名逻辑
git clone <repo> && cd sunflowerTime

# 2) 重建 key.properties（4 行；密码从离线备份取，勿提交）
cat > android/key.properties <<'EOF'
storePassword=<密码>
keyPassword=<密码>
keyAlias=upload
storeFile=upload-keystore.jks
EOF

# 3) 出包
/Users/wangjunchao/development/flutter/bin/flutter build appbundle --release
```

### 4.2 出包命令

| 用途 | 命令 |
|---|---|
| 本地测试包（APK） | `flutter build apk --release --obfuscate --split-debug-info=build/symbols` → `build/app/outputs/flutter-apk/app-release.apk` |
| 上架包（AAB） | `flutter build appbundle --release --obfuscate --split-debug-info=build/symbols` |

> ⚠️ **2026-10-11 防逆向批次起，release 出包必须带 `--obfuscate --split-debug-info`**（Dart AOT 符号混淆；无此参数 = Dart 类名/函数名明文，可被 blutter 等工具直接还原）。
> **每次发版必须归档两份符号文件**（`build/` 已被 `.gitignore` 忽略，不会自动留存）：
> 1. Dart 符号：`build/symbols/app.android-arm*.symbols`
> 2. R8 映射：`build/app/outputs/mapping/release/mapping.txt`
> 两者是解混淆崩溃栈的唯一钥匙，按版本号另存离线归档（如 `symbols-archive/v1.2.3/`）。

### 4.3 验签命令


## 5. ⚠️ 风险与纪律

1. **`.jks` 是有意入库的**（方案 A：私有仓库 = 备份），依赖 `android/.gitignore:17` 的取反规则 `!/app/upload-keystore.jks`。
   - **若仓库将来要转公开，必须先更换密钥**，或先把 `.jks` 从 Git 历史里彻底清除（否则等同于公开了签名身份）。
   - 密码不入库 → 密钥库即使泄露也**打不开**；密码与密钥库分开保管 → 一方丢失仍可恢复。
2. **切换签名会导致 `adb install -r` 失败**：debug 签名与 release 签名不一致 → `INSTALL_FAILED_UPDATE_INCOMPATIBLE`。真机首次试装 release 包前**必须先卸载**旧包，而**卸载会清空 App 本地数据**（植物 / 阳光 / 专注记录）。请务必知情后再操作。
3. **密钥库不可重建**：文件一旦生成，**不要删掉重建**。重建 = 换签名 = 老用户无法升级。
4. **release 包的 R8 / 资源压缩现状（2026-10-11 防逆向批次更新）**：
   - 此前实测：AGP 9.0.1 下 release **默认开启 R8 代码压缩与混淆**，但工程未显式配置、无自定义 keep 规则、`shrinkResources` 关闭、Dart 侧无混淆——**符号基本裸奔**。
   - **2026-10-11 起已显式加固**（`android/app/build.gradle.kts` release 块 + 新增 `android/app/proguard-rules.pro`）：
     | 层 | 措施 | 状态 |
     |---|---|---|
     | Java/Kotlin 宿主层 | `minifyEnabled = true`（显式声明，与 AGP 默认一致） | ✅ |
     | Java/Kotlin 资源 | `shrinkResources = true`（**新增**，清 androidx 冗余资源） | ✅ |
     | JNI/反射保险 | `proguard-rules.pro`：keep `net.zetetic.database.**`（SQLCipher JNI）、`com.it_nomads.fluttersecurestorage.**` | ✅ |
     | Dart AOT（`libapp.so`） | 构建命令 `--obfuscate --split-debug-info=build/symbols`（**R8 管不到 libapp.so，必须靠这个参数**） | ✅ 出包命令已更新（§4.2） |
     | DB 口令 | `kDatabasePassphrase` 仍为 Dart 明文常量——**值不可改**（改了已装设备老库解不开），挪存储形式（NDK 拼装等）另行评估 | ⏸ 单独决策 |
   - **含义**：release 与 debug 的**行为可能有差异**——R8 只裁剪 / 混淆 **Java/Kotlin 宿主层与插件类**（Dart 侧 AOT 代码 `libapp.so` 不受 R8 影响，靠 `--obfuscate`）。差异集中在**反射 / JNI / MethodChannel** 路径。
   - **首次装机冒烟重点**（反射 / JNI / MethodChannel 三类路径）：① 入口页「屏蔽通知（勿扰）」开关（MainActivity MethodChannel）② 音效/背景音出声（just_audio）③ 专注页亮屏常亮（wakelock_plus）④ 打盹屏方向检测（native_device_orientation）⑤ 家长 PIN 锁与设置持久化（flutter_secure_storage / shared_preferences）。
   - `mapping.txt` 用于 crash 堆栈还原（归档纪律见 §4.2）。
