## 1. ② 家园（Home）——本批核心构想

### 1.1 玄参原意

- 现在阳光只有**花园**和**商店**两个消耗出口；想新增第三个：**家园**。
- 目的：让孩子知道家里的**水、电、燃气、食物**等资源都是来之不易的。
- 形态：APP 里一个新页面（tab 或花园旁入口），家园需要**建设**：
  - 花费阳光**生产电力**；
  - 花费阳光**购买水源**；
  - 花费阳光**购买食物**；
  - 等等。
- **随机事件小卡片**：偶尔弹出「家里快没电了 ⚡，是否消耗阳光购买电力？」之类的提醒，孩子自己做决定。

### 1.2 AI 初步可行性（未评审，仅预判）

**可行，且结构上几乎是「花园养护」的换皮 + 一个倒计时资源池**，复用度高：

| 复用点 | 对应既有机制 |
|---|---|
| 资源条（电/水/燃气/食物 4 槽） | 花园养护度（4 槽：浇水/施肥/除虫/松土）同构 |
| 随机事件卡 | Boss 战召唤小怪 / 护眼卡的全屏 modality 卡手顺已有 |
| 阳光扣费 + 家长审批 | 商店兑换链路原样复用（家长点确认才真扣——**经济铁律不动**） |
| 数值驱动 | 全部进 `prd_params.dart` 常量 + 护栏测试，沿用既有纪律 |

**设计要点（立项时需拍板的）**：
1. **资源衰减节奏**：每天掉多少？掉光了会怎样（家里「停电」黑暗一天？还是纯软提示不惩罚）？——涉及挫败感，需谨慎，倾向**软后果**（不惩罚完成度，只展示状态）。
2. **花费 vs 收益**：这是**纯消耗出口**（阳光 Sink），符合经济系统需要更多 Sink 的大方向；建议不给反向收益（家园不给阳光），否则变成新农场。
3. **随机事件频率**：每天 0–2 次，防打扰；事件内容可扩展（水管漏了/燃气要换）。
4. **入口形态**：第 6 个 tab？还是花园页内二级入口？——孩子端 5 tab 结构是玄参拍板过的，倾向**不新增 tab**。
5. **教育闭环**：每次购买可配一句「电是从发电厂来的，要花很多煤」之类的科普文案。

**风险**：内容生产量比农场大（4 种资源 × 状态图 × 事件卡文案/美术）；M4 后才有排期空间。

## 2. ① 农场（Farm）——2 可，暂缓

- 与花园机制高度重复（种植→养护→收获），对孩子认知增量小，**倾向不开**。
- 保留价值：若未来需要更多阳光 Sink，**家园已能覆盖**；农场可作为花园「第 N 块地」的扩展而非独立玩法。
- **结论：搁置，记录在案。若家园落地后仍缺 Sink 再翻出来。**

## 3. ③ 传奇植物许愿树（Wish Tree）——远期构想

### 3.1 玄参原意

- 触发条件：**花园种满了**（30 块地全成株？待定义）。
- 孩子可以在许愿树**许愿**——说出自己想要的东西；
- 许愿树能「长出」孩子想要的东西，**拿去跟家长兑换**。

### 3.2 AI 初步可行性

- 本质是**愿望清单（Wishlist）+ 家长兑换**，与商店「家长定制奖励」天然衔接：
  - 孩子许愿 = 提交一条「非标奖励申请」；
  - 家长端审核（同意/拒绝/协商替代品）= 商店兑换审批链路的变体。
- 「传奇植物」包装：许愿消耗高价值资源（阳光大额 / 稀有种子 / 满养护植物的结品？），让「许愿」本身也有代价，防止滥用。
- **设计要点**：家长端需要「愿望审核台」；愿望与商店奖励（定制奖励）数据模型可合并。
- **风险**：孩子会许「现实里买不到」的愿（想要恐龙），文案需引导「许个家长能兑现的愿」。
