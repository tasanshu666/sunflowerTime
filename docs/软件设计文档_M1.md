## 3. 专注引擎 FocusEngine（T06）

### 3.1 设计要点

1. **纯 Dart**：不 import flutter（`FeedbackLevel` 因此下沉到本文件，见 §5），可被 `dart test` 直接驱动。
2. **时钟注入 + 外部 tick**：`FocusEngine({planned, clock})`，内部**零 Timer**；时间前进由外部调用 `tick(now)` 驱动。这是可测性的关键——单测能完全控制时间轴，不必 `await` 真实秒数。
3. **状态机**：`idle → running → (absent | paused) → finished`。

### 3.2 产出规则（PRD §4.1.5）

| 状态 | 行为 |
|---|---|
| 在场（running） | `1 阳光/分钟`（`kSunlightPerFocusMinute`），按秒浮点累计 |
| 离席（absent） | 产出**停止**，不扣减已有产出；**不冻结会话倒计时**（倒计时按墙钟走，与顶部 mm:ss 同源） |
| 恢复在场 | 速率自"检测到在场的时刻"起算，`kResumeSeconds`(10) 秒内**线性回到 100%**；离席窗口**不补产出** |
| 暂停（paused，退出确认） | 倒计时与产出**双双冻结** |

**10 秒斜坡用解析积分**（`_rampIntegral`，∫rate dt）而非逐帧近似，因此"10 秒斜坡恰好产出 `5/60` 阳光"是精确值、可直接断言（QA 用例 C1/C3 在逐秒 tick 与一次性 tick 两种驱动下均得同值）。

**absent 与 paused 的区别（易混，务必分清）**：

| | 倒计时 | 产出 | 触发 |
|---|---|---|---|
| `absent` | 继续走 | 停止 | 灭屏（系统级） |
| `paused` | 冻结 | 冻结 | 竖屏 / 返回键 → 退出确认框 |

### 3.3 四档反馈事件与声量账（PRD §4.1.3 / §4.1.4）

| 档位 | 触发 | 呈现 | 是否占声量账 |
|---|---|---|---|
| `lvl1` 常态产光 | 全程默认 | 呼吸式明暗 | 无声 |
| `lvl2` 随光报信 | 会话进度每过 1/3（`kReportBoundaryFractions`，天然 2 次） | 送出一粒光 + 气泡 | 不占 |
| `lvl3` 欢迎回来 | 离席后恢复在场 | 纯视觉光晕 | 无声 |
| `lvl4` 唤醒 | 离席持续 90s（轻声）/ 180s（加重） | 睁眼 + 语音（M1 为文案占位） | **占** |

- **声量账**：`lvl4` 每场 ≤ `kWakeMaxPerSession`(3)，其中"加重"≤ `kWakeStrongMaxPerSession`(1)。
- **打断**：离席累计 300s（`kL3ThresholdSeconds` + `kInterruptSeconds`）→ 本次专注**自然结束**；已产出阳光**按实际专注分钟全额保留**（§4.1.4 明写不砍半）。
- **达声量上限后只抑制语音，时间轴照走**：即使 3 次唤醒已用尽，300s 仍会打断（QA 用例 F3 专门验证）。
- **最短结算**：实际专注 < `kMinFocusMinutes`(5) → `shortAborted`、无产出；**打断场景同样要求 ≥5 分钟才计产出**（§6.2 明写"主动退出与被动结束口径一致"，QA 用例 H1/H2 验证）。

### 3.4 ⭐ 共享推进内核 `_advance(now)`（本批最重要的设计）

**起因**（缺陷 B22，由 QA 独立验证发现）：

初版 `onAbsent()` / `onPresent()` 更新状态时**没有推进 `_lastTick`**（而 `resume()` 有），两者不对称。后果链：

1. 真机灭屏时 Flutter Timer 会被系统挂起 → **离席期间一个 tick 都不会发生**；
2. 亮屏回来后首个 tick 用 `now - _lastTick` 计算，把**整段离席时长当作 running 吞入**；
3. 三重后果：① `actualFocusMin` 注水（可能误越 5 分钟门槛）；② 结算按注水时长发阳光 → **等于给离席时间发阳光**（直接违背用户刚拍板的灭屏口径）；③ 离席满 300s 的**打断被整段跳过**。

**修法**（工程师采用，优于"在事件入口补 `_lastTick`"的朴素方案）：

抽出共享内核 `_advance(now)`，让 tick 与两个事件入口**共用同一套"按当前状态切分时段归属"的逻辑**：

```
tick(now)            → _advance(now)
_advance(now)        → 按【当前状态】结算区间 [_lastTick, now] 的时长归属
                        running → focusSeconds + 阳光（含斜坡积分）
                        absent  → absentElapsed + _checkWake()
                       最后更新 _lastTick，再做「到时」判定
onAbsent([now])      → 先 _advance(t) 把「截至离席时刻」的在场时长结算掉，再翻 absent
onPresent([now])     → 先 _advance(t) 把整段离席窗口（即便期间 0 次 tick）按 absent
                       归属并触发唤醒/打断；若已在其中打断则直接返回，
                       否则才翻 running + 起 10s 斜坡 + 发 lvl3
```

**为什么优于朴素方案**：只在 `onPresent` 里补 `_lastTick = now` 会把整段离席窗口"当作不存在"，虽然治好了注水，却会让**离席满 300s 的打断整段丢失**。共享内核让"无 tick"与"有 tick"两条路径结果一致——QA 用例 L1/L4 直接证明了这一点（离席 60s「完全无 tick」vs「每 10s tick」→ `actualFocusMin` / 阳光 / 事件档位计数**完全一致**）。

**验证锚点**：在场 10s + 离席 60s（0 tick）+ 恢复 → `actualFocusMin = 11/60`（修复前为 71/60）。

### 3.5 时序语义（OS 挂起 ticker 下的必然取舍，需知悉）

当 ticker 被系统挂起时（离席期间 0 tick），`lvl4` 唤醒与 300s 打断都在**恢复调用 `onPresent` 时**才被补判：

- **真实世界时刻 ≠ 语义时刻**：孩子已经回来了才收到「想你了」语音，冗余但无害，声量账仍只计一次；
- `FocusSession.end` 由页面传 `DateTime.now()`，即**恢复时刻**而非真值 300s 时刻。

这是"不引入前台服务"前提下的取舍；若后续 G1 实测发现该语义影响数据质量，再评估前台服务（架构 §9 Q1 的延后项）。

## 4. 在场检测 PresenceDetector（T07）

### 4.1 两路独立信号（不可混为一谈）

| 信号 | 触发 | 语义 | 消费方行为 |
|---|---|---|---|
| `onAbsent` / `onPresent` | 系统灭屏 / 亮屏 | **离席**（产出停止 / 恢复） | 引擎停产出、进唤醒时间轴 |
| `onPortraitIntent` | 物理竖屏 | **退出意图**（§4.1.6） | 暂停 + 「确定结束吗？」确认框 |

架构 §1.3 将「物理竖屏 **OR** 手动退出（返回键）」归为同一条退出路径 → 页面侧把两者收敛到同一个 `_requestExit()`。

### 4.2 实现要点

- **灭屏判定**：`WidgetsBindingObserver.didChangeAppLifecycleState`（Android 灭屏 → `inactive`/`paused`）。
- **方向**：`native_device_orientation` 的**传感器模式**（`onOrientationChanged(useSensor: true)`）——必须用传感器模式，窗口模式读的是被 `SystemChrome` 锁死的 UI 方向（B12 的教训）。
- **纯函数化**：`classifyPresence()` / `classifyOrientation()` 抽为纯函数，便于单测。
- **B18 两处保护完整保留**：`kOrientationGraceSeconds`(3s) 宽限期 + `_armed` 武装条件（必须先观察到一次横屏，之后的竖屏才算退出意图）。

### 4.3 未启用信号（登记待确认）

`touchTimeoutEnabled`（"长时间无触摸"）**留接口、M1 默认关闭**。理由：PRD §4.2 规定打盹屏**无操作区、不可交互**，而 §4.3 又把"长时间无触摸交互"列为离席信号之一——两者在 MVP 基线下**缺少有效输入源**。待产品确认后决定是否补前台触摸监听。

## 5. 四档反馈与向日葵画布（T08）

### 5.1 `FeedbackLevel` 下沉（架构调整，需知悉）

T06 要求引擎"纯 Dart 不 import flutter"，而原 `FeedbackLevel` 定义在 `sunflower_canvas.dart`（依赖 material）。故：

- 全工程**仍只有一个** `FeedbackLevel` 定义，无重复、无循环依赖。

### 5.2 画布新增参数

| 参数 | 用途 |
|---|---|
| `progress` | 0..1 会话进度，驱动"每过 1/3 送出一粒光" |
| `welcoming` | 欢迎回来光晕（lvl3） |
| `celebrating` | 结算"醒着庆祝"态 |

保留 4 秒呼吸动画与"慢而不突、零突事件"原则（§4.1.1）。

### 5.3 台词（PRD §4.1.3 三原则）

| 档位 | 文案 |
|---|---|
| lvl2 随光 | 「我去把它放好。」（只报信，不夸奖，说完转身继续做自己的事） |
| lvl4 轻声 | 「向日葵想你了，回来看看吧」 |
| lvl4 加重 | 「休息一下就回来哦」 |

三原则落地：① 随光只报信不夸奖；② 夸奖只留给结算动画与家长转述；③ 任何一档不得比结算动画更诱人（防"故意走神只为看朋友说话"的反向激励）。

### 6.2 ⚠️ 返回语义（M0 三次真机事故定稿，本批继续遵守）

**铁律：`context.go()` 是替换路由栈，不是入栈。** 凡 `go` 进入的页面，栈中没有"上一页"，`Navigator.pop()` 会把最后一个页面弹掉 → 黑屏。

本批落实：
- 打盹屏结束 → `context.go('/settle', extra: ...)`（**非** pop）；
- 结算页 / 入口页退出 → `context.go('/')`；
- 打盹屏外层 `PopScope(canPop: false)` 拦 Android 返回键 → 走「暂停 + 确认」（否则栈底按返回会直接退出 App）。

### 6.3 打盹屏布局（PRD §4.2）

- 顶部**只留**「本次 mm:ss / mm:ss」，不显示阳光池数字；
- 中央向日葵（低亮、呼吸、零突事件）；
- **无任何操作区**，退出仅靠竖屏动作；
- 离席时降亮提示；恢复时 lvl3 光晕。

### 6.4 结算页

光回罐动画（光点从屏外飞回罐子 + 数字滚动上涨）+ 本次专注时长 / 产出阳光 / 当日累计 + 向日葵庆祝态；**预留"家长转述表扬"占位区**（M2 夸夸台接入）。

### 6.5 入口页

选时长（`kFocusDurationOptions` = 15/20/25/30/45，缺省 20）+ 音效/背景音乐开关（**占位**，未接 settings Repository）+ 「把手机横过来放好」引导。

## 7. 阳光记账与软顶（T10）

### 7.1 计算公式（PRD §4.5 公式①）

```
S        = 专注阳光（引擎积分产出） + 任务数 × kTaskSunlightReward(12) × 完美日系数
有效阳光  = min(S,60) + max(0, min(S,90)-60)×0.5 + max(0, min(S,110)-90)×0.2   （日上限 79）
```

- 任务模块在 **M3**，本批任务数**参数化传 0**（不写死）；
- 软顶**直接复用** `core/utils/math_ext.dart` 的 `computeSoftCap()`，**未重复实现**分段公式。

### 7.2 ⭐ 单源修正（缺陷 P2-1）

初版存在**产出双源**：引擎 `FocusOutcome.rawSunlight` 走斜坡积分（精确），而 `SunlightService.settle()` 用 `actualFocusMin` 重算 S（忽略斜坡）→ **每次"离席后恢复"多算 5/60 阳光**，引擎那套精确积分被白做。

**修正**：`computeRawS` 的参数由 `focusMin` 改为 `focusSunlight`，`settle()` 内部改用 `outcome.rawSunlight`；**对外签名不变**（仍收 `FocusOutcome`），调用点无需改动。QA 用例 N1 证明账本 `gross` 与引擎 `rawSunlight` 一致。

### 7.3 记账时序（架构 §3.2）

```
结算 → computeSoftCap(S) → 账本 append(gross=S, net=有效, balanceAfter=余额+net)
     → 保存 FocusSession
```

- `shortAborted`（<5 分钟）**不写账本**，但仍保存会话记录；
- 账本 append-only，`gross`/`net` 同时落库 → 审计可还原「原始 S=162 → 实得 79」。

### 7.4 `FocusLocalRepository` 真实实现

替换 M0 的 `FocusLocalRepositoryStub`：`saveSession` / `sessionsOfDay` / `countValidFocusDaysLastWeek`（后者用 `kValidFocusMinutes`(15) + `kCompletionRateThreshold`(0.90) 判定有效专注日）。
