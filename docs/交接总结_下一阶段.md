## 2. ⛔ 上架硬阻塞（不修就发不出去）

### 2-1. `release` 构建用的是 **debug 签名**（P0）

```kotlin
// android/app/build.gradle.kts:28-34
buildTypes {
    release {
        // TODO: Add your own signing config for the release build.
        // Signing with the debug keys for now, so `flutter run --release` works.
        signingConfig = signingConfigs.getByName("debug")
    }
}
```

release 包用 debug key 签名 —— **无法上架**（Google Play / 国内渠道都会拒）。修法：生成正式 keystore（`keytool -genkey`）→ 建 `key.properties`（**必须加进 `.gitignore`**）→ `build.gradle.kts` 读取并签 release。

### 2-2. `applicationId` 是 `example` 占位且与 iOS 不一致（P0）

```kotlin
// android/app/build.gradle.kts:18-19
// TODO: Specify your own unique Application ID ...
applicationId = "com.example.sunflower_time"
```

| 平台 | 当前值 | 问题 |
|---|---|---|
| Android | `com.example.sunflower_time`（**带下划线**） | `example` 是占位域名，上架必须换成自有域名反写（如 `com.sunflowertime.app`） |
| iOS | `com.example.sunflowerTime`（camelCase） | 与 Android **不一致**（F31，`docs/bug记录表.md` 已登记） |

⚠️ **改包名的连带影响**（这是为什么它值得单独立项，而不是顺手改）：
- 老用户的本地数据（Drift + SQLCipher 库）**存在私有目录里，包名一换就找不到**
- 所有 `adb` 脚本、真机调试命令里的包名都要同步改（当前纪律见 `docs/bug记录表.md` F31）
- 需要一次性决策：**是否提供数据迁移**（本地单机 App 没有账号，迁移只能靠导出/导入）


理由：把「不需要决策的」和「需要您拍板的」分开 —— 前者可以连续推进不打断，后者攒成一批一次性拍板。美术是**唯一可完全并行**的一条线，所以先把它解锁（①）。
