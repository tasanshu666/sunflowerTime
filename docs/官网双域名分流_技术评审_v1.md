> 本文档只回答一件事：**同一台服务器上，如何让 `sunfocused.cn` 与 `sunfocused.top` 展示不同内容、且符合各自的备案要求。**
> 不涉及产品功能设计，不涉及 App 端改动。

---

## 1. 工作来源：这件事为什么必须做

### 1.1 业务背景

产品《小小葵番茄钟》采用**一次性买断**模式：

- iOS 已上架，售价 **$3.99 / 中国区 ¥29.90**，走 Apple 内购；
- Android **不上任何应用商店**（国内买断制无法在国产品牌商店上架，详见关联文档 §1），改为**官网直供 APK + 激活码解锁**；
- 因此官网必须承担：产品介绍、APK 下载、**在线付款**、激活码发放。

### 1.2 合规来源：为什么不能用一个域名搞定

付款环节要求「**网站备案主体 = 收款商户主体**」（支付宝、微信支付的硬性审核项）。而目前两个域名分属不同主体：

| 域名 | 备案主体 | 备案号 | 归属管局 |
|---|---|---|---|
| `sunfocused.cn` | 个人（北京） | 京ICP备2026070040号-1 | 北京市通信管理局 |
| `sunfocused.top` | 个体工商户（河北唐山） | 待申请 | 河北省通信管理局 |

收款商户号开在**个体工商户**名下，因此**收款行为只能发生在 `sunfocused.top` 上**。

### 1.3 一条不能绕开的合规红线

依据《互联网信息服务管理办法》，ICP 备案分**经营性**与**非经营性**两类。**个人备案的网站只能用于非经营性用途**，不得承载商品销售、在线收款等经营活动。

个人备案的 `sunfocused.cn` 一旦出现「立即购买」入口或收款链接，属于备案性质与实际用途不符，后果是：

- 轻则被管局要求限期整改；
- 重则被注销备案号（该域名将无法在大陆访问）。

**所以这不是「想不想分开」的问题，是「必须物理分开」的问题。**

### 1.4 为什么不能直接放弃 `.cn`

`sunfocused.cn` 目前承载 App Store 上架时填写的**隐私政策页面 URL**。iOS 已上线，该链接不能失效，否则会在 App Store 页面出现 404，影响用户信任与合规审查。

因此 `.cn` 必须保留可用，但**只承担非经营性展示职责**。

## 2. 目标与非目标

### 2.1 目标

| # | 目标 | 验收方式 |
|---|---|---|
| G1 | 两个域名各自解析到独立内容，互不串页 | 访问两个域名得到不同页面 |
| G2 | `sunfocused.cn` 上**不存在**任何购买/收款入口 | 全站抓取无 `/buy`、无收款链接 |
| G3 | `sunfocused.top` 承载完整官网 + 购买页 + 下载页 | 功能可用 |
| G4 | App Store 的隐私政策 URL 继续可用 | `sunfocused.cn` 隐私政策页返回 200 |
| G5 | 两个站点各自悬挂自己的备案号 | 页脚核对 |

### 2.2 非目标（明确不做）

- ❌ 不做两套独立的产品官网（`.cn` 只做极简展示 + 隐私政策，不做第二个完整站）
- ❌ 不做域名之间的自动跳转（见 §5 风险说明）
- ❌ 不改动 App 端任何代码
- ❌ 本次不涉及支付接口对接（支付接入另行评估）

## 3. 硬性约束

| # | 约束 | 说明 |
|---|---|---|
| C1 | **两个站点内容物理隔离** | 不是样式隐藏，是文件不存在 |

| C5 | `sunfocused.top` 域名有效期须 > 3 个月 | 备案硬性要求 |

## 4. 技术方案

### 4.1 总体思路

**不是「一个网站绑两个域名」，而是「一台服务器运行两个站点」。**

HTTP 请求头中的 `Host` 字段标识用户访问的是哪个域名，Web 服务器据此将请求路由到不同的站点根目录。这意味着：

- 可共用同一台服务器、同一个公网 IP、同一个 443 端口；
- 通过 TLS 的 **SNI** 机制在同一端口上提供两张不同证书；
- 两个站点在文件系统层面完全独立，一个站点的文件不会被另一个站点访问到。

### 4.2 站点划分

| 站点 | 域名 | 职责 | 内容 |
|---|---|---|---|
| A 站 | `sunfocused.cn` | 非经营性展示 | 极简品牌介绍页、隐私政策页、联系方式 |
| B 站 | `sunfocused.top` | 经营性官网 | 完整产品介绍、购买页、APK 下载、订单/发码接口、隐私政策 |

**A 站内容要求**：不得出现价格、不得出现「购买」「解锁」「立即开通」等任何引导交易的文案与按钮，不得链接到 B 站的购买页（可链接到 B 站首页，但不建议）。

### 4.3 目录结构（建议）

```
/var/www/
├── site-cn/                    # A 站根目录 · sunfocused.cn
│   ├── index.html              # 品牌介绍（无任何交易入口）
│   ├── privacy.html            # 隐私政策（App Store 使用）
│   └── assets/
│
└── site-top/                   # B 站根目录 · sunfocused.top
    ├── index.html              # 完整官网
    ├── buy.html                # 购买页（仅此站存在）
    ├── download.html           # APK 下载
    ├── privacy.html            # 隐私政策（副本）
    ├── assets/
    └── (服务端接口由反向代理转发)
```

> 若现有官网使用静态站点生成器或前端框架，建议通过**构建参数**产出两份产物（一份不含购买模块，一份含），分别部署到上述两个目录，避免两套源码长期漂移。若现有站点规模较小，直接维护两份静态文件亦可接受。

### 4.4 Nginx 参考配置

```nginx
# ===== A 站：sunfocused.cn（个人备案 · 非经营性） =====
server {
    listen 443 ssl;
    http2 on;
    server_name sunfocused.cn www.sunfocused.cn;

    ssl_certificate     /etc/nginx/ssl/sunfocused.cn.pem;
    ssl_certificate_key /etc/nginx/ssl/sunfocused.cn.key;

    root  /var/www/site-cn;
    index index.html;

    # A 站不提供任何下单接口
    location /api/ { return 404; }
}

# ===== B 站：sunfocused.top（个体户备案 · 经营性） =====
server {
    listen 443 ssl;
    http2 on;
    server_name sunfocused.top www.sunfocused.top;

    ssl_certificate     /etc/nginx/ssl/sunfocused.top.pem;
    ssl_certificate_key /etc/nginx/ssl/sunfocused.top.key;

    root  /var/www/site-top;
    index index.html;

    # 下单 / 发码 / 支付回调（具体实现另行设计）
    location /api/ {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}

# ===== HTTP 统一跳转 HTTPS =====
server {
    listen 80;
    server_name sunfocused.cn www.sunfocused.cn sunfocused.top www.sunfocused.top;
    return 301 https://$host$request_uri;
}
```

**若使用宝塔面板**：等价操作为「网站 → 添加站点」两次，分别绑定两个域名、指定各自根目录，并在每个站点内申请免费 SSL 证书。底层生成配置与上文一致。

### 4.5 证书

两个域名各自申请独立证书（Let's Encrypt 免费即可）。同一 443 端口靠 SNI 区分，无冲突。

> 注意：`sunfocused.top` 的证书需在其备案通过、域名正式解析后再申请，否则 HTTP-01 验证会失败（备案未通过时域名被阻断）。如备案期间确需准备，可用 DNS-01 方式提前签发。

### 4.6 上线顺序（重要，不可颠倒）

```
① 服务器与目录准备（可提前做，不影响线上）
        ↓
② 提交 sunfocused.top 的 ICP 备案（河北管局）
   ⚠️ 此时 .top 不得解析、不得对外开放，网站保持关闭
        ↓
③ 备案通过，取得备案号
        ↓
④ 配置 DNS 解析 + SSL 证书 + 页脚挂备案号
        ↓
⑤ 验收（见 §6）
```

`sunfocused.cn` 全程不受影响，**不需要停站**。

## 5. 明确禁止的做法

### 🔴 禁止用前端 JavaScript 判断域名来隐藏购买入口

例如用 `location.hostname === 'sunfocused.cn'` 判断后隐藏按钮。

**为什么禁止**：

1. 购买链接仍在 HTML 源码中，管局核查或第三方抓取页面源码即可发现；
2. 搜索引擎爬虫、监管扫描工具多数**不执行 JavaScript**，抓到的就是完整页面；
3. 这不是「隔离」，是「遮挡」，一旦被认定备案性质与实际用途不符，后果由备案主体承担。

**正确做法**：A 站的目录里根本不存在购买页文件，`/buy` 请求直接 404。隔离发生在服务端文件层面，不在样式层面。

### 🔴 禁止 `.cn` 302/301 跳转到 `.top` 的购买页

个人备案域名跳转到经营性页面，同样可能被认定为用于经营活动。如确需引导，`.cn` 可链接到 `.top` 的**产品介绍首页**，不直接跳购买页。

### 🔴 禁止两站共用同一个站点根目录

共用目录意味着文件天然互通，等于没有隔离。

## 6. 验收标准

| # | 检查项 | 通过标准 |
|---|---|---|
| V1 | 域名分流 | 访问 `sunfocused.cn` 与 `sunfocused.top` 返回不同页面 |
| V2 | 内容隔离 | `sunfocused.cn/buy` 及任何购买路径返回 **404** |
| V3 | 源码洁净 | 抓取 `sunfocused.cn` 全站源码，**搜索不到**「购买」「¥29.9」「支付宝」「微信支付」等字样 |
| V4 | 隐私政策可用 | `sunfocused.cn/privacy`（或现有路径）返回 200，内容完整 |
| V5 | 备案号 | `.cn` 页脚为京ICP备2026070040号-1；`.top` 页脚为对应河北备案号；均可点击跳转工信部 |
| V6 | 证书 | 两域名 HTTPS 均无警告，证书域名匹配 |
| V7 | 接口隔离 | `sunfocused.cn/api/*` 返回 404，不转发到后端 |
| V8 | 响应式 | 两站在移动端（375px 视口）无横向滚动、无元素溢出 |

## 7. 风险与依赖

| # | 风险/依赖 | 影响 | 处置 |
|---|---|---|---|
| R1 | `sunfocused.top` 备案被驳回 | 整条线上线延后 | 河北要求：通讯地址须与执照地址同市（唐山）；手机号须归属河北/北京/天津；营业执照「字号」情况决定以企业还是个人名义备案 |
| R2 | `.top` 后缀信任度低于 `.cn`/`.com` | 用户对官网可信度存疑，可能影响支付转化 | 建议同时注册 `sunfocused.cn`（已持有）与 `.com` 备用；页面加强资质展示 |
| R3 | 备案期间误开 `.top` 访问 | 管局退回，重排 7–10 工作日 | 上线顺序（§4.6）中把 DNS 解析放在备案通过之后；部署时用 hosts 本地验证 |
| R4 | 两站内容长期不同步 | 隐私政策版本不一致，合规瑕疵 | 隐私政策单一来源，构建时复制到两个目录 |
| R5 | 支付接口尚未对接 | 验收项 V3 的完整验证需等接口就绪 | 本期只做静态分流，接口层留占位 |

### 需要网站团队确认的信息（评审时请回复）

1. 现有 `sunfocused.cn` 站点的**技术形态**：纯静态 HTML / 静态生成器 / 前端框架 / 服务端渲染？
2. 服务器环境：Nginx / Apache / 其他？是否使用宝塔等面板？
3. 现有站点是否与 App 或其他服务共用同一套代码仓库？
4. 隐私政策页当前的确切路径（用于验收 V4）。
5. 是否有 CDN 或对象存储前置？若有，需同步配置域名回源与证书。
6. 预计工时与排期。

## 9. 参考依据

- 《互联网信息服务管理办法》（国务院令第292号）第四条：经营性/非经营性分类管理
- 《非经营性互联网信息服务备案管理办法》（信息产业部令第33号）：向**主体住所所在地**省通信管理局备案
- 河北省通信管理局备案要求：未备案成功的网站必须关闭；个体工商户按有无字号区分备案名义；通讯地址与证件住址不得跨市
- 支付宝、微信支付商户接入要求：网站备案主体须与商户主体一致
