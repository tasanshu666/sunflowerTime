## 3. 已锁定口径（13 条 · 白纸黑字 · 不得改语义）

| # | 维度 | 定稿口径 |
|---|---|---|
| 1 | 能量体系 | 新大招能量**独立一套**，与现有守卫入场券能量完全并存；不碰旧 `balance`、不改旧能量经济。 |
| 2 | 攒能量 | 按**累计在场专注分钟**攒，30 分钟 = 1 格，不足 30 分钟的零头**保留进度**（不清零、不取整丢弃）。 |
| 3 | 上限与跨天 | 最多 2 格；**跨天不清零**（已攒格数与零头进度都保留）。 |
| 4 | 能量条 | 显示在向日葵战士**头顶**；满格即时点亮；未满格显示**进度百分比**。 |
| 5 | 释放入口 | 守卫战斗过程中**点击向日葵战士**释放大招。 |

| 7 | 清怪与闪避 | 大招**无视闪避**（实现上不走子弹路径即可天然绕开闪避判定）；释放即清除**当前已出场的怪**（walking 状态的怪），不是全体撤退/逃跑。 |
| 8 | 收益 | 大招击杀**算战果/可计入通关**，但**不给掉落奖励**（阳光/宝箱等）。 |
| 9 | 特效 | 大招特效释放在**怪物聚集区**（横向通道），不是战士脚下。 |
| 10 | 素材范围 | 本轮**只接大招**：「释放大招」27 帧（720×720）+「大招特效」27 帧（1470×630）+ 两段 mp4 提取音轨；帧须转 webp 适配现有帧播放器；其余待机/受击/胜利/未命名 mp4 **已接入过，本轮不动**。 |
| 11 | 门控 | 「只对付费版开启」——复用现有**一次性买断**（无订阅/无账号）；新增一个 `FeatureKey` 走门控矩阵单点；默认安全回退免费档。 |
| 12 | 免费版表现 | **锁定态 + 点击引导**：免费版能量条**照常显示并累计**到 2 格，但能量格打 🔒 标记明确提示是买断功能；点战士**弹买断引导**（不静默失败、不无响应）；买断后已攒能量**立即可用**（不需重攒）。 |
| 13 | 购买页卖点 | 本轮**不把「守卫大招」加进家长端购买页卖点对比表**（规避宣传描述与实际功能不符的审核风险，也不动对比表行数守卫测试）。 |

## 4. 产品定义

### 4.1 产品目标（3 个 · 正交）

- **G1 给「普通攻击」之外一个爽点**：守卫战从「只能等它打完」升级为「我攒了能量、我能在关键时刻放一发」，让孩子在守卫过程中有一次主动决策。
- **G2 把长期专注兑现成即时战果**：专注分钟不再只在报告里是数字，而是攒成看得见、会慢慢涨的能量条，在守卫战里直接兑现为「清场」。
- **G3 零经济冲击、零宣传风险**：新能量与旧入场券能量、阳光、掉落完全隔离；不新增货币、不改门控经济、不动购买页卖点表。

### 4.2 用户故事

- 作为**孩子**，我专注了半小时后发现战士头顶能量条亮了一格，我知道再攒一格就能在守卫时放一次大招。
- 作为**孩子**，守卫战里怪物聚过来了，我点一下向日葵战士，它放出大招把眼前这批怪全清掉，但不会给我阳光或宝箱——我图的是「守住了」。
- 作为**孩子**，我一场战斗里攒了两格，先放一次、过一会儿再放一次，两次都能生效。
- 作为**免费版用户**，我看到能量条照常在涨，但格子上有 🔒；点战士时弹的是买断引导，不是点了没反应。
- 作为**买断用户**，我买断前已经攒满的两格立刻可用，不需要重新专注。
- 作为**家长**，我确认大招只影响守卫战表现，不额外产币、不写进购买页卖点，描述与实际一致。

## 5. 状态机与口径定义

### 5.1 大招能量状态模型

```
UltimateEnergy = { filledCells: 0..2, fractionMin: 0..29 }   // 0..29 为当前未满格的零头分钟进度
```

| 项 | 定义 |
|---|---|
| 状态变量 | `filledCells`（已攒满格数，整数 0/1/2）+ `fractionMin`（当前未满格的零头分钟，0–29） |
| 攒能量 | 按**累计在场专注分钟**（来源：`FocusEngine.actualFocusMin`，跨专注会话累加）递增；每满 30 分钟 → `filledCells += 1`，`fractionMin` 减去 30 后的余数保留 |
| 上限 | `filledCells` 最大 2；满 2 格后不再产生第 3 格（边界处理见 §10-待明确问题 B1，已给推荐默认） |
| 百分比 | 未满格显示 `fractionMin / 30`（保留一位小数，如 29/30 = 96.7%）；`fractionMin = 0` 且未满格时显示 0% |
| 释放消耗 | 每次释放 `filledCells -= 1`；`fractionMin` **不受影响**（释放只扣整格，不动零头进度） |
| 跨天 | `filledCells` 与 `fractionMin` **都不清零、不做 expire**；与旧 `GuardEnergy.balance` 的跨天 expire 逻辑无关 |
| 持久化 | prefs / JSON，**不依赖 schema 变更**；`schemaVersion` 恒 32，不新增数据库列 |

### 5.2 状态转移示例（用于验收对表）

| 累计在场专注分钟 | filledCells | fractionMin | 能量条表现 |
|---|---|---|---|
| 0 | 0 | 0 | 两格均空，0% |
| 15 | 0 | 15 | 第 1 格 50%，未满 |
| 29 | 0 | 29 | 第 1 格 96.7%，未满 |
| 30 | 1 | 0 | 第 1 格点亮；第 2 格 0% |
| 44 | 1 | 14 | 第 1 格点亮；第 2 格 46.7% |
| 59 | 1 | 29 | 第 1 格点亮；第 2 格 96.7% |
| 60 | 2 | 0 | 两格均点亮（满能量） |
| 跨天前 59min → 次日重新打开 | 1 | 29 | 与跨天前完全一致，不清零 |
| 满 2 格后释放一次 | 1 | 0 | 点亮 1 格，可再次释放 |

### 5.3 释放与战斗状态

| 环节 | 定义 |
|---|---|
| 入口 | 守卫战斗进行中，点击向日葵战士（`soldierRect` 区域，当前无 `onTap`，本轮新增） |
| 前置条件 | 付费档且 `filledCells >= 1`；免费档一律不释放，走买断引导（见 5.4） |
| 清怪 | 清除**当前已出场且处于 walking 状态**的怪（不是 `_retreatAll` 全体撤退/逃跑，也不清未来的波次） |
| 闪避 | **无视闪避**：实现上不走子弹到达路径 `_processBulletArrival`，故不触发闪避判定 |
| 战果 | 大招击杀**计入战果/可计入通关**；**不产生任何掉落奖励**（阳光/宝箱等） |
| 特效位置 | 锚定**怪物聚集区（横向通道）**，非战士脚下；随释放动作与音轨同步 |
| 多次释放 | 一场战斗内可释放多次，每次扣 1 格，直至 `filledCells = 0` |

### 5.4 免费档锁定态状态机

```
免费档 + 任意能量状态：
  能量条：照常显示、照常累计（与付费档同一套状态与来源）
  能量格视觉：叠加 🔒 标记，明确提示「买断功能」
  点击战士：→ 弹买断引导（showPremiumUpsell），不静默失败、不无响应、不消耗能量

买断后（同一设备、无需账号、无需重攒）：
  🔒 移除 → 已攒的 filledCells / fractionMin 立即可用
  门控判定：默认安全回退免费档（无法确认买断态时按免费处理）
```

## 10. 待明确问题（边界口径 · **已给推荐默认，不需玄参再裁定**）

> 逐条审视 13 条口径：**未发现内部硬矛盾，也未发现技术不可行点**（大招绕开子弹路径天然满足「无视闪避」）。
> 以下为口径未覆盖、但实现必然遇到的**边界空白**，本文给出推荐默认，交由架构师按此落地；若架构师发现与代码现实冲突，经 team-lead 中转反馈，不直接改口径语义。

- **B1｜满 2 格后继续专注的溢出分钟如何处理？**
  口径 2（累计分钟）+ 口径 3（上限 2 格）蕴含溢出边界，13 条未明写。
  **推荐默认**：满 2 格后 `fractionMin` 停止累计（能量池已满，不再产生第 3 格，也不无限增长持久化数字）；释放一格后从 0 重新开始攒零头。
  **理由**：避免长期用户累计分钟数无界膨胀，且与「最多 2 格」直觉一致；不影响任何已锁口径语义。

- **B2｜付费档能量为 0 时点击战士的表现？**
  口径 5/6 定义了「有能量时点战士释放」，未定义 0 格时点击。
  **推荐默认**：不触发清场、不消耗，给一次性轻提示「能量不足，专注可攒能量」（走 i18n）；不得静默失败到让孩子以为坏了。
  **理由**：与 C62 纪律一致（可点但无响应会被当成 bug）；不改变消耗规则。

- **B3｜大招清场与波次调度的关系？**
  口径 7（清当前已出场怪）+ 口径 8（可计入通关）需明确「清掉当前波后是否还来下一波」。
  **推荐默认**：大招**只清当前 walking 怪，不改波次调度**；后续波次按既有 `step()` 节奏继续 spawn；通关仍按既有「波次打完 + 场上无怪」判定，大招击杀的战果正常计入。
  **理由**：把大招定义为「清场」而非「终止战斗」，与口径 7 完全一致，也避免大招变成跳过整场的作弊入口。

- **B4｜「累计在场专注分钟」的会话归属与中断计量？**
  口径 2 写「累计在场专注分钟」，需明确来源是每次专注会话的 `actualFocusMin` 之和，而非守卫战斗时长。
  **推荐默认**：来源为 `FocusEngine.actualFocusMin` 跨会话累加；专注中途退出的实际分钟照常计入（以引擎已落库的值为准）；守卫战斗时长**不额外产出**大招能量，避免「战斗→能量→大招」自循环。
  **理由**：与 §7-C4 一致，且守住「能量来源于专注」的原始立意（原文第 1 句）。

- **B5｜新能量是否按 childId 隔离？**
  现有部分 prefs 存储为设备级、不带 childId；新能量若走 prefs 需明确归属。
  **推荐默认**：**由架构师定**，但需与既有 `GuardEnergy` prefs store 的归属策略保持一致（若旧能量为设备级则同策略，不单方面引入 childId 维度），避免两份能量在不同维度上错位。
  **理由**：口径 1 要求两套能量「完全并存」，归属维度不一致会让「独立」变成「错乱」；此处只给约束，不替架构师选存储方案。
