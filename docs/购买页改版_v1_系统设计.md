### 4.1 B 组（买断后解锁 · 4 行）——**从矩阵派生**

| 行序 | 项目名 `label` | `FeatureKey` | 免费列（`featureQuotaFor`/`allowed`, free） | 买断列（premium） |
|---|---|---|---|---|
| 1 | 花园「一键操作」 | `oneClickCare` | ✗（`freeEnabled=false`，见矩阵 L94-99） | ✓ 不限 |
| 2 | 花盆上限 | `gardenPotCapacity` | 4 个（`kFreeGardenPotQuota`=4） | ✓ 最多 12（`kPremiumGardenPotQuota`=12） |
| 3 | 成长项模板 | `taskTemplateCount` | 5 条（`kFreeTaskQuota`=5） | ✓ 不限（`kUnlimitedQuota`） |
| 4 | 奖励模板 | `rewardTemplateCount` | 5 条（`kFreeRewardQuota`=5） | ✓ 不限 |

## 6. 空间硬约束（平板 ×1.3 + 窄屏）

**口径（C61/C65，`lib/shared/responsive.dart`）**：
- 平板判定 = `shortestSide ≥ kTabletShortestSideThreshold`（`responsive.dart:24-32`）。
- **文字**：走 `MediaQuery.textScaler`（`app.dart` 单点注入 1.3×），**组件内不得再乘 `uiScaleOf`**（否则双重缩放 = C75 ⑤ 教训，`focus_level_badge.dart:159-161` 有前车之鉴）。
- **图形/定尺寸元素**（行高、徽标、圆角、间距）：显式乘 `uiScaleOf(context)`（`responsive.dart:42`），手机端恒 1.0 → **零回归**。

**对比表专项硬约束**：

| # | 约束 | 判据 |
|---|---|---|
| S1 | 三列在**窄屏 320dp** 不水平溢出 | widget test：`MediaQuery(size: 320×640)` 下 `tester.takeException()` 为 null，无 `RenderFlex overflowed` |
| S2 | **文字不手动缩放**（只吃 `textScaler`） | 源码守卫：表格组件内 `Text.style.fontSize` 为**裸常量**，无 `* uiScaleOf` 乘在 fontSize 上 |
| S3 | 行高/胶囊内边距/圆角随平板放大 | `44 * uiScaleOf(context)` 等；手机 = 44（零回归） |
| S4 | textScaler **1.3 且窄屏 320** 叠加仍不溢出 | widget test：`MediaQuery(size:320, textScaler: TextScaler.linear(1.3))` → 不溢出 |
| S5 | 项目名长词可换行 | `_Cell` 内 `Text(maxLines: 2, overflow: TextOverflow.ellipsis)` |
| S6 | 平板内容居中限宽 | 复用现有 `ListView` + 页宽上限策略（与 `parent_settings_page.dart` 一致即可，本批不引入新限宽常量） |

> ⚠️ 若工程师发现 `Table` 在此三列 + ×1.3 下不好控，**降级方案**：三列 `Row` + `Expanded(flex: 16/10/10)` + `CrossAxisAlignment.stretch`，每列 `Container` 自绘（买断列带渐变）。
